## 七个场景的 CHECK 与公式

### ⑦ wakecutover：终审 7a

`cutover.i`：HLS 有声源进入 B holding 后读回 `vid=no,mute=yes`；调用 setKeepAlive(false)，5 秒内 open 新 HLS。服务拦住新源响应，等旧恢复窗口超过 6 秒才释放，用来覆盖旧恢复超时重置新首帧闸门的竞争。随后读取新源首帧并连续采样原生身份。

CHECK 数字：`wakeUs/openUs/deltaUs/holdingPhase/held/expectedPath/frames/nativeSamples/renderEpoch`。

公式：`holding && held.vid=no && held.mute=yes && 0<=deltaUs<5,000,000 && count(newURI.MovaFirstFrame)>=1 && all(nativeSamples.path==expectedPath)`。首帧按事件所属新 URI 过滤；旧源恢复事件不能代替。新首帧后继续观测约 6 秒。总计 10/10 才满足本行；保留 MovaKeepAliveResume 事件用于复核。

### ⑧ edgepause：终审 7b / A10 fallback

`pause.i`：先播放直播，配置 backToLive=reopen；本地响应闸门确认旧 live.m3u8 的网络重开已进入但尚未释放，记录网络响应未释放和 backToLiveEdge Future 是否仍 pending（后者仅诊断，命令接受可早于网络完成），再调用 pause，释放响应，持续观察 6 秒。

`fallback.i`：allowHls=false 进入 fallback；在该相位调用 backToLiveEdge，等待同样的网络窗口，不额外调用 pause，确认此操作本身不补播。

CHECK：`pendingAtPause/futurePending/networkWindow/phase/pauseUs/atPause/nativeSamples/after/bufferEvents`。

公式：pause 子项 `pendingAtPause && all(native.pause=yes) && !playing && !playbackIntent`；fallback 子项 `pendingAtPause && phase=fallback && all(native.pause=yes) && !playing && finalPhase=fallback`。fallback 可保留原始播放意图，不能错误要求 intent=false。两类各 10 次，原生响应窗口未出现不判通过。

### ⑨ errclass：错误分级与 poster

- `nonfatal.i`：播放中对真实 mpv 下 sub-add 坏字幕，保留 error 级 KERNEL_LOG 和 MovaErrorEvent。数字 `before/after/errors/state/overlay`；公式 `exists(error.fatal=false) && state.error==null && !overlay && after.timePosMs>before.timePosMs`。若当前 mpv 不输出符合内核过滤器的 error，**BLOCKED（刺激未成立）**，不注入假事件凑数。
- `fatal.i`：recovery 默认关闭，真实 HTTP 404；独立弱客户端事件泵读取 END_FILE 原因码。数字 `endFile/errors/state/overlay/text/spinnerCount`；公式 `END_FILE.reason=4(error) && exists(error.fatal=true) && state.error!=null && !buffering && spinnerCount=0 && overlay`。遮罩按真实树中的 MovaStrs.playbackError 检查。
- `poster.i`：createMova 不显式开 preciseFirstFrame，让真实 MovaPlayer(poster:) 自行启用；Timer 观察真实 AnimatedOpacity，记录初始显示和首次 opacity=0 的时刻（淡出开始，比完全撤掉更严格）。数字 `frames/posterHiddenObservedUs/opacity/posterSamples/native`；公式 `signal=restart && opacity=0 && firstHiddenUs>=firstFrameUs`。观察精度为 UI 调度/采样精度，不宣称像素级精确时刻。

三类各 5 次。

### ⑩ probe：A12/N6

- `list.i`：真实 Video 挂树，避免 MovaPlayer 的 UI 探测入口；命令式 open HLS 后等待列表，验证播放器主动探测。
- `manual.i`：只拦截 Dart UA 的探测响应，mpv 媒体请求继续；确认 probeEntered 后手选实际 720p，再释放探测。
- `once.i`：默认 MovaPlayer + 播放器自动入口 + 多次显式 loadQualities，共享同会话探测。
- `failover.i`：先成功播放并探测 primary.m3u8；服务使主地址后续请求 404，由 MovaFailoverOnly 切到 master.m3u8，再读取列表和请求数。不是只用冷启动 404→好地址冒充重探测。
- `disabled.i`：probeVariants=false，默认 MovaPlayer 挂树后播放，不调用显式 loadQualities。

共同数字：`qualities/currentQuality/probeCounts/probeTotal/sourceIndex/native/fixture`；服务请求日志分开记录 Dart probe 与 mpv 媒体请求。

公式：list `qualities.length>0`；manual 再要求 `currentQuality=720p && native.path contains /720/`；once `probeTotal=1`；failover `sourceIndex=1 && primary/master 各存在一次探测 && 每地址计数=1 && 列表非空`；disabled `probeTotal=0`。前三类各 10，后两类各 5。

### ⑪ manageauto：A16 / A11 租约

此树没有 cp0_autotier.py 和 cp0_autotier_auto.dart，不能从其他忙碌 worktree 取文件。本次在 CP1 服务中实现三档实时 HLS 和 ts 限速（16,000 bytes/s），不伪造 buffering。起播通过 hls-bitrate=max 选择高码率，ABR 默认策略阈值设为 1，加快真实卡顿刺激。

- `managed.i`：manageAuto=true，等待真实 MovaAbrDownShift；解除限速后手选 720p 验证仍能操控，保留全部降档事件及 URI。
- `default.i`：manageAuto 缺省 false（配置对象默认），记录 30 秒限速观察窗中的事件和档位。
- `disabled.i`：同一夹具 ABR enabled=false 对照，记录相同数字；不和 CP0 比较。
- `lease.i`：直播手选档，记录实际起始 buffering、随后 true/false 事件及 MovaAbrDownShift 数。

managed/default/disabled 数字 `downShifts/downShiftCount/autoTierAfter/manualAfter/native/stats`；managed 公式 `downShiftCount>=1 && manualAfter=720p && native.path contains /720/`，以“还能手选”验证未永久屏蔽；另外两类要求 `downShiftCount=0`，原始数字供 CP0 对照。lease 数字 `beforeBuffering/bufferEvents/downShiftCount/quality/native`，公式 `false→true→false && downShiftCount=0 && quality=720p`。各 5 次。

### ⑫ bblock：B04 / N3

`restore.i`：进入前宿主读 settings screen_brightness、dumpsys display/window；createMova 声明 allowedOrients=[portraitUp]，宿主先锁竖屏。播放后宿主在真实视频左侧上滑改亮度，随后全屏/退出/释放，各阶段读取原文。

数字：`seed/changed/seedTolerance/changedNative/before/fullscreen/exit/after`。解析显式保存系统亮度、display 设置/应用覆盖、rotation、statusBars/navigationBars 的 InsetsSource visibility。公式 `abs(seed-before.seedBrightness)<=0.02 && changed!=seed && applicationOverrideChanged && settings/display/applicationOverride restored && exit/after.rotation==before.rotation && exit/after.insets==before.insets`。0.02 为播种量化容差，原始值同时留档；还原比较原始值，不用此容差掩盖还原差异。

解析只认明确字段；OEM 输出缺失、多种 rotation、缺任一系统栏、未知归一化亮度均 BLOCKED，不猜。亮度恢复还会对账窗口覆盖，避免只看本来未变的 settings 得出假阳性。

`preview.i`：真实预览 VTT 请求返回 404 header，Content-Length 声明大 body、只发少量字节后挂起；服务 hangingBody=true 后 dispose。数字 `disposeUs/disposeCompleted/nativeReleased/fixture`；公式 `completed && disposeUs<=5,000,000 && NativePlayer.disposed=true`。后者结合 dispose Future 已完成证明主内核所有者释放；不在已销毁句柄上调用 mpv。服务最终释放挂起连接。两类各 5 次。

### ⑬ pool：B11/B12

`reject.i/throw.i`：固定一播放器池先播 A，宿主 beforeOpen 对 B 分别拒绝/抛错，再重试同一 B。界面按真实 pool.slotFor(index).ready 决定 MovaPlayer 或占位；失败时验证占位实际挂树，成功后检查原生地址。

数字 `before/after/expectedPath/hiddenOnReject/threw/ready`；公式 `hiddenOnReject && ready && after.path==expectedPath && throw行为符合变体`。各 5 次。

`feed.i`：真实 MovaFeed 连续 activate 1000 条，固定三播放器 audioOnly，用本地小素材循环；记录全程 maxCache，每 100 条同步宿主 dumpsys meminfo，返回十点 PSS、cacheCount、pending、movaCount。缓存允许半径 max(pool.size,prefetchDepth)=3，上界 2×3+1=7。

数字 `items/maxCache/cacheBound/samples/adjacentDeltasKb/pssSlopeKbPer100Items/strictlyIncreasing/slopeCriterion/criterion`。OLS 斜率 `sum((i-4.5)*(pss[i]-mean(pss)))/82.5`，单位 KB/100 条。CHECK 中写明趋势判据 `!(strictlyIncreasing && slope>0)`，并要求 `maxCache<=7`；十点必须齐全。这里“单调爬升”取九个相邻差值都 >0，不引入未批准的绝对内存上限。正斜率但有回落会留下数字供复核，不宣称排除泄漏。共 3 轮。
