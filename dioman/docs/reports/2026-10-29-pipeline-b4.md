### I3 与 I7

- I3：沿用 `InvariantHarness`，对真实 share/offline 组合同时断言 api.pending、保留上下文的取消订阅、FakeClock.pendingTimers。首发取消后、共享尚未结束时就检查其订阅已摘除，避免仅在最后 state.dispose 清表而掩盖泄漏。最后订阅者离开也要清理离线队列和共享令牌。
- 白盒诊断经公开管理 API 读取：share 四表的 activeEntries、cache 的 pendingWrites/entryCount。专用用例在请求结束后检查屏障为零，clear/dispose 后内存与活动表为空；在途屏障只保留到 finally，不依赖 LRU 淘汰通知。
- I7：mock 探测→回落使用嵌套 `{'items':[{'n':0}]}` 和原地修改 Transformer，无 retry/auth 参与的一轮独立击中 mock markReplayable 变异；share.retry 另有无外层 retry 的独立测试，避免其它插件的声明掩盖缺陷。
- 本批使用专用不变量组合；完整 512 子集 powerset 仍按实施计划由后续整体验证批次承接，不把这些专用测试冒称完整 powerset。

## 规格不清与保守取舍

### 终审裁决

1. **终审已裁决：share 订阅者超时**：整体上限为 `connectTimeout + receiveTimeout`；仅当 `request.data != null` 时再加 `sendTimeout`。任一参与项为 null 或 ≤0 即整体不限时，与 Dio 对 null/零的语义一致。保留每订阅者独立的 ctx.wait，不模拟 Dio 的阶段进度；废弃最小正值规则。连接 5s、接收 30s 的跟随者可等待传输 10s 后成功。
2. **终审通过：cache 插件级 clock 与 §8.1 的统一时钟表述**：本任务与 §5 要保留 clock，本批提供可选 `DiomanClock`，只控制 TTL；省略沿用客户端时钟。请求级 now 没有恢复，等待计时始终使用 ctx.wait/客户端时钟。构造器 TTL 时钟覆盖有专用回归。
3. **终审通过：cache remove 的失效范围**：旧实现提升全局代次；本批只使指定 key 的在途读取/写入失效，clear 仍作废全部。这样删除单项不会丢弃无关 key 的在途写入，已在行为变化列出；终审确认保留此行为变化。
4. **终审通过：持久化结果元信息**：显式 shouldStore 可接受失败，必须保留分类；因此写入 Map 增加 result 字段，旧格式仍可读。持久化后端需要保留扩展字段；不假设旧两字段能表达非 200 状态。

### 已按规格处理

- `DiomanCacheOptions.maxEntries` 是占位字段，删除；`DiomanCache.maxEntries` 是实际 LRU 能力，保留。默认重试次数从旧实现核实为 3，不采用临时实现时的 1。
- 缓存命中和 share 跟随者不进入传输，不代表它们绕过 outer/auth。旧清单中写到上游拦截器跳过的行按固定阶段的新语义承接。
- mock 探测标记只存 StateKey，不写请求头或 extra；探测结束 finally 恢复，回落重新参与 share/cache。标记只影响来源，不修改 key 协议。
- end/race 底层传输独立；订阅者提前离开不取消其它请求，也不因首发逻辑收尾清掉仍在使用的下游等待。胜出后的迟到响应不重新发布。
- shouldCache/shouldStore/fallbackWhen/shouldQueue 抛错均由管线边界转 internal，落定原错误；连通流错误按通知类隔离并记录。
- share/cache 的诊断 API 只读，用来观察内部活动表与屏障，没有恢复旧登记簿或手工结算概念。
- 不可重复消费的 Stream 仍遵从 B1 的重放保护限制：无法克隆时保留引用并 debug 告警，不承诺把单订阅流变成可重放流。
