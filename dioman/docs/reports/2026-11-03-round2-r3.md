## 原生槽与落定

1. DiomanContextState 持有唯一 nativeSlot、当前 nativeResult 和 nativeClosed；派生 ctx 复用该状态。结果只带一个无原生引用的身份凭证，copy/derive/create 路径维护它，observeNative 将匹配派生结果重新绑定到槽内 response。公开 getter 最终用 identical 严格匹配当前结果，拒绝串用。
2. 传输每次尝试写最新 response/raw/error，成功显式写 null error。缓存命中、本地拒绝和 share 跟随者没有自身匹配槽；mock 探测调用真实传输时照常有槽。
3. 落定先记录匹配 native，再经工厂生成 debug/raw 副本；原生字段在 create 返回后附加。internal 按 failure.error/errorStack 原栈重抛，缺 error 时 StateError，缺 stack 时 StackTrace.current。reject 和可预期失败抛出在同一个 finally 内，转换期间仍能读取最终结果对应的 native。
4. finally 无条件清空槽和当前结果并设置封闭标记，不依赖共享传输的 retain/release 是否结束。writeNative 和 observeNative 都拒绝落定后的迟到写入。
5. Retry-After 在所有原生响应的归一化边界统一抽取单个原始头值；多值头忽略，避免正常 HTTP 响应被可选头转成 internal。retry 只经内部入口读字符串；share 与内存快照保留该小事实，内联 mock 同样适用。持久化不增加字段。
