## 规格不清与保守取舍

### 需要终审确认

1. **BaseOptions 无显式字段集合**：构造后无法区分省略与显式 `responseType: json`、`method: GET`、默认布尔值、空地址/null。因此 envs 与 extend 共用“非空/非默认字段合并”的策略，显式非默认 overrides 在 setup 后优先，三类 Map 深克隆后按顶层键合并。不能用 BaseOptions 的默认值把继承的非默认值重置回默认；已在 extend 公共契约注明。若必须支持此类重置，需要后续裁决带 absent 哨兵的专用配置补丁 API，不能通过猜测显式传参解决。
2. **connect 的真实计时证据**：本批测试确认 connect 配置到达 adapter，并注入 connectionTimeout 验证新入口落定；真实回环只能稳定测 send/receive。迁移 integration.md:90 的 SYN 黑洞/丢包真实计时仍需 B7 netem，不能把本批的注入测试当作真实连接超时完成。报告逐行表保留此限制。

### 已按规格处理

- 迁移 rule.md:245 的旧 keep 描述含“请求 enabled=true 可重启插件级 false”，与插件规格 §0.2 冲突；遵循新规格：编译时整体跳过，任何请求选项都不能重启，已有回归。unit 中旧 ordering 的相对次序由固定阶段替代。
- loading 按回调**身份**分组；0→1 请求决定 delay，1→0 请求决定 delayClose；dispose 后 API 数量归零、取消所有 timer、关闭已显示回调，在途和旧链不再通知。I2 与 I4 由 Harness 真正安装插件记录；I4 用 ctx.id，即使两个调用拿到同一个结果对象仍分别计数。
- notify 的 stringify 与 notify 作为同一通知动作隔离，与 axp B2 参考一致；filter predicate、timeout probe、envs rule 的错误作为 bug 原样抛出。错误日志默认输出不被 debug=false 静默掉，用户日志器/默认输出抛错也不影响请求。
- notify 接收 DiomanResponse<dynamic>；扩展字段必须经 is 检查，遵循 B1 不强转任意 R 的终审裁决。
- repath 遵循旧 Dart 的 containsKey 语义：query 存在但值为 null 时优先编码为字符串 null；不回退到 data。只处理 Map 请求体，query/hash/authority 不替换；filter ignoreValues 保留 Dart 相等语义，NaN 的豁免可使用 ignoreKeys 或自定义 predicate。
- timeout 的四档/空字段/缺档/按档并集沿用旧语义；底层真实计时由 Dio 执行。没有引用新 Dio 才有的 transformTimeout，未提高依赖最低版本。
- 跨 auth/retry/share/cache 的清单行，本批用透明等待、重复 next、同结果复用、source 短路与失败替身验证 loading/notify 外层契约；替身没有实现相应插件策略，后续批次仍须真实装配验证。

## 终审修复

`codex review --uncommitted` 正常结束，原文见 [codex-review](pipeline-b2-evidence/codex-review.txt)。一项 P2 成立：absolute URL 没有路径时，authority 正则没有以 ?/# 为边界，会把 `https://example.test?next=/{id}` 的 query 内容当路径替换。修为 `://[^/?#]*`，新增 query 和 fragment 两种无路径 URL 回归。撤掉修复的失败证据：[review-url-authority](pipeline-b2-evidence/review-url-authority.txt)。

自查另修：配置递归克隆的顶层 Map 必须物化为 Map<String,dynamic>（不能强转动态 Map）；loading 的日志器随显示状态持有以避免计时隐藏后残留独立登记；extend 非默认 Dio 字段随最终覆盖保留；通知错误默认记日志。最终 analyze、97 测试与 13 文件覆盖率均在最终实现上重新运行。
