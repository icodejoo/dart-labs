## TL;DR

- get/post/put/patch/delete/head/request/send 增加可选 decode；成功落定后独立转换，失败不调用。解码程序错误原对象原栈抛出，不经过插件，不改写成 parse。
- 插件实例 dispose 返回 FutureOr<void>，客户端 dispose 返回 Future<void>。同步取消并拒绝新请求，逆注册顺序串行等待清理，尽力全部执行后原栈抛出首个错误；重复调用共享完成信号。
- 两份 README 已有覆盖八种失败和 null 的穷举 switch，保留并编译验证。resolveOption 未知类型报错与 R2b 未装插件告警已覆盖、不改；新增 debug 下 retry.jitter 和 cache.clone 的字段类型检查。
- 全量 5682 项通过，比 R4 增加 22 项，含 512×10 powerset 与 I1–I11。全部 lib/src 可执行行 1681/1681、分支 800/800，均 100%；两类定向变异全部击中并按 SHA256 恢复。
- SDK 保持 ^3.5.0，不新增依赖；未修改 benchmark/、tool/、docs/README.md、0002 或设计文档。未运行基准。

## 新旧 API 与落定边界

| 旧写法或类型 | R5 写法或类型 |
|---|---|
| api.get<User>(path) 只做运行时转型 | api.get<User>(path, decode: User.fromJson)，不传 decode 时保留原行为 |
| api.send<User>(method, path) | 可加 decode，返回 DiomanResponse<User>，data 已转换 |
| DiomanPluginInstance.dispose(): void | FutureOr<void>，同步插件无需改签名 |
| Dioman.dispose(): void | Future<void>；需要等待资源或捕获清理异常时 await api.dispose() |

decode 在 _dispatch 返回后执行，插件链、取消检查、reject、原生槽封闭及 pending 注销都已完成。数据入口只有成功才返回到解码步骤；send 显式判 result.ok，失败保持原返回路径。decode 抛 DioException、FormatException 或其他错误也直接交给调用方，不经过传输或协议错误分类。解码回调应只读输入数据；共享的原始 Map/List 不做额外深拷贝。

客户端 dispose 自身不是 async 方法，先保存唯一 Future、标记销毁并 cancelAll，再启动逆序清理。同步实例在原调用栈内完成；遇 Future 则等待结束才处理下一项。重复调用在清理进行中和结束后都返回同一个 Future。安装失败仍保留 setup 首次异常，无法 await 的回滚会立即启动清理并隔离其异步错误。内置插件实现与资源语义未修改。eject 的异步清理由客户端继续跟踪，dispose 也会等待已移除实例并报告首个观测错误；同步 eject 的清理错误仍直接抛出。

## 自审

codex review --uncommitted 已结束，退出 0，发现 1 项 P2，成立并已修复：eject 原先丢弃异步清理返回值，错误会成为未处理异步异常，后续客户端销毁也无法等待。

修复后 eject 仍返回 bool，异步完成信号进入客户端跟踪集合，完成后移除；异常被立即观测并保留原栈。dispose 在逆序调用所有已注册实例后，一并等待已移除实例，最后抛首个观测到的清理错误。销毁开始后拒绝 eject，避免已捕获实例被再次清理。新增两个最低层用例覆盖成功信号尚未完成、失败先于销毁被观测、重复清理防护。定向修复验证 30 项全部通过。

审查为只读，没有运行额外测试或基准；没有让其他代理执行实现工作。原始审查日志仅在 coverage/r5-review.log，摘要见 [review.json](round2-r5-evidence/review.json)。

## 需终审确认

1. 异步 dispose 的返回类型是公开破坏性变化；同步取消和拒绝保证保留，等待清理和捕获异常需迁移为 await，已写入两份 README、公共注释和迁移指南。
2. G4 的连接超时黑盒验证缺口仍为 1，本轮没有扩大基线。
3. 可能影响性能，终验复测。
4. 项目 SKILL 要求新增报告更新 docs/README.md，与本任务明确禁止修改索引冲突，按用户指令保留索引。0002 和设计文档未修改；未发现需要修改响应契约的矛盾。
