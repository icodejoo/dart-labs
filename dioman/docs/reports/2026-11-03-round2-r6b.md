## TL;DR

- 新增 `Dioman(deadline: Duration?)` 与 `DiomanCall(deadline: Duration?)`；请求级非空值优先，均为 null 时不限；零或负值立即到期。`extend` 继承客户端默认预算。
- 入口以 `DiomanClock` 建立单一整体预算，不随重试重置，覆盖重试等待、刷新排队、离线队列、share 等待和完整传输（含响应体）。到期取消自身内核令牌，结果为 `timeout`、`reason: 'deadline'`，不是 cancel；internal 仍优先原栈抛出。
- 最终全量 5704 项通过、0 失败、0 跳过，包含 5120 项 powerset；I1–I11 夹具全绿。全部 37 个 lib 文件核对，36 个 lib/src 文件的可执行行与分支 100%。具体计数见下表。
- 真实验收计划 12 场景 × 七网络 × 双风格 = 168 格：26 格真实通过、0 失败、142 格因契约未声明网络而不适用，缺能力跳过为 0。**不能将这次写成 168 格真实通过**；当前 testkit 只有 26 个已定义适用格。
- 闸门退出 0；G0/G1/G2/G3/G5=0，G4=1 保持 connect 超时的既有基线。三类变异均由断言击中并按 SHA256 恢复。自审 1 项 P2 已修。

## 语义与归属

预算独立于 timeout 插件及 Dio 的 connect/send/receive 阶段计时，不以阶段超时之和代替。请求级 null 沿用客户端默认；有效预算为 null 才不限。用户令牌在计时前接入，首次用户取消保留 cancel 类别与原因。到期、成功、失败、异常出口都清理入口预算计时器；保留共享传输的状态也不会保留已落定调用方的预算计时器（I3）。

share start/retry 的传输使用独立令牌；首发或跟随者到期只退出自身，最后一个订阅者离开才取消传输。end/race 由调用方自身预算到期触发撤回，回退有效参与者；不按共享结果类别推断撤回，延续 B8 与 I8。没有改写 share 仲裁算法。

## 自审与修复

`codex review --uncommitted` 已结束，退出 0，发现一项 P2：breaker 将非空 ctx.cancelled() 一律当取消，截止失败不进 shouldTrip，半开探测也无法因到期重新打开。现将自身最终条件归一后，只跳过真正的 cancel；timeout/deadline 进入默认或自定义失败策略。新增 3 个参数化回归，修复前默认与自定义 true 两项实际失败，修复后全部通过；自定义 false 仍能否决熔断，普通取消既有用例保持通过。

另在自主复核时保留传输出口的 internal 优先级，新增“parse 回调在到期同时抛错”回归，防止整体预算吞掉程序错误。[审查摘要](round2-r6b-evidence/review.json)，原始日志在 coverage/r6b-review.log。

执行偏差：自审命令内部额外运行过 `dart test --reporter compact`，未带用户要求的 `--concurrency=1`，并把附加输出写入 TEMP。这不符合本批运行约束；附加日志已复制到 coverage/r6b-review-extra-tests.log，未将这轮作为正式验证证据。正式全量各轮均显式 concurrency=1，没有与真实验收或另一个 Dart 测试进程并行；真实验收前自审进程已结束。未调用协作代理。

## 需终审确认

1. 当前 testkit 只定义 26 个 timeout-total 适用格，无法在保持契约的同时交付“168 格全部真实执行”。若终验要求七网络都实际执行，需先在 testkit 另批定义其余 142 格的中立预期；本批未擅自改动。
2. 请求级 null 采用沿用客户端默认的标量覆盖语义；有效预算 null 不限，零/负值立即到期。不另加三态“显式关闭客户端默认”的 API。
3. G4 仍为 `DiomanTimeouts.connect#effective:no-real` 一项既有基线。
4. 自审命令内部默认并发全量属于上述执行偏差，正式串行结果与它分开取证。
5. 性能复测按要求推迟到终验前；未运行基准，未改 benchmark/ 或基准脚本。未新增依赖，SDK 仍为 ^3.5.0。
