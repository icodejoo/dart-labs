/// 公开插件边界的计时探针；只用于定位线索，不替代无探针的 A/B。
class _Probe extends DiomanPlugin<DiomanResponse<dynamic>> {
  const _Probe(this.stage, this.enforce, this.samples);
  @override
  final DiomanStage stage;
  @override
  final DiomanEnforce enforce;
  final Map<String, List<int>> samples;
  @override
  String get name => 'profile:${stage.name}:${enforce.name}';
  @override
  DiomanPluginInstance<DiomanResponse<dynamic>> setup(
          Dioman<DiomanResponse<dynamic>> client) =>
      _ProbeInstance(name, samples);
}

/// 每客户端独立探针，记录包含内层的耗时。
class _ProbeInstance extends DiomanPluginInstance<DiomanResponse<dynamic>> {
  _ProbeInstance(this.name, this.samples);
  final String name;
  final Map<String, List<int>> samples;
  @override
  Future<DiomanResponse<dynamic>> handle(
      DiomanContext<DiomanResponse<dynamic>> ctx,
      DiomanNext<DiomanResponse<dynamic>> next) async {
    final watch = Stopwatch()..start();
    try {
      return await next();
    } finally {
      (samples[name] ??= []).add(watch.elapsedTicks);
    }
  }
}

# dioman

Dioman brings authentication, retries, caching and the rest of your request policies together around Dio, for Dart and Flutter.

## Purpose

Request policies get harder to maintain when each interceptor has to understand the backend envelope and coordinate with every other interceptor. Dioman gives your app one request entry point and normalizes results before plugins see them, so auth, retry and cache can work with the same business status instead of each decoding it again.

The pipeline wraps each attempt in a predictable order. When auth refreshes a token or retry sends again, that attempt naturally passes through the inner cache, share and mock layers. The kernel keeps cancellation attached to the whole call and loading callbacks paired through those waits. You configure the policies you need without wiring their cleanup and replay paths together.

Start requests through the Dioman client to get this behavior. Its underlying Dio still handles transport and Dio interceptors; calling Dio directly runs those interceptors alone.

## Installation

```sh
dart pub add dioman
```

Requires Dart ^3.5.0; Dio is the only runtime dependency.

## Quick start

The quick start uses inline routes and runs offline. Remove DiomanMock when connecting to your backend.

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')),
      plugins: [
        const DiomanRepath(),
        const DiomanFilter(),
        DiomanMock(routes: {
          'GET:/users/42': (_) => {'code': 0, 'data': {'id': 42}},
          'GET:/health': (_) => {'code': 0, 'data': 'ready'},
        }),
      ]);
  try {
    final data = await api.get<Map<String, dynamic>>('/users/{id}',
        query: {'id': 42});
    print(data);
    final result = await api.send<dynamic>('GET', '/health');
    print('${result.kind.name}: ${result.status} / ${result.httpStatus}');
  } on DiomanResponse catch (failure) {
    print('${failure.kind.name}: ${failure.message}');
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

## Results

Use get/post/put/patch/delete/head when you want the data, or send when you also need the DiomanResponse metadata. Verb methods throw a failed result that you can catch; send lets you inspect the same failure as a return value. Programming errors keep their original exception and stack. If your app has its own failure type, configure reject to map expected verb-method failures.

Result fields: `ok`, `kind`, `status` (logical status), `httpStatus`, `code`, `message`, `data`, `reason`, `request`, `raw`, `error`, `errorStack`, `callSite`.

Kinds: `ok`, `http`, `biz`, `network`, `timeout`, `cancel`, `parse`, `auth`, `breaker`, `offline`, `internal`.

By default, a response is treated as an envelope when it contains code and at least one of data/message, and is unwrapped once. If your backend uses another format, customize detection, success codes and logical status with Envelope and DiomanResponseFactory. Set call.envelope=false to keep the original data for one call.

## Plugins

Fixed stages: outer → prepare → attempt → credential → source → Dio.

Install the plugins your app needs, then adjust a call with DiomanCall(options: {Plugin.option: value}). Set a value to false to skip that policy, true to reuse its configuration, or an options object to override individual non-null fields. Each plugin also has an installation-level enabled switch. Cache and share need an explicit per-call opt-in; the other installed plugins participate by default.

### Loading

Loading keeps one display cycle around a logical call, including token refresh, cache hits, shared requests and offline waits. Your UI receives a paired open and close even when the call is cancelled.

Options: `delay, delayClose`. Full parameters and defaults: [plugin spec](docs/design/pipeline-plugin-spec.md).

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')),
      plugins: [DiomanLoading(onChanged: (visible) => print(visible))]);
  try {
    final result = await api.send<dynamic>('GET', '/items',
        call: DiomanCall(options: {DiomanLoading.option: false}));
    print(result.kind);
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

### Auth

Auth protects all requests by default and shares one refresh operation within a client. Implement onRefresh to fetch and save the new token through an independent client. The renewed value below only illustrates updating the store.

Options: `tokenManager, onRefresh, onAccessExpired, onAccessDenied, onFailure, isProtected, ready, expiresAt, refreshLeeway, headerKey, buildHeader`. Full parameters and defaults: [plugin spec](docs/design/pipeline-plugin-spec.md).

import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

class Tokens implements DiomanTokenManager {
  @override
  String? accessToken = 'demo';
  @override
  String? refreshToken;
  @override
  void setTokens({required String accessToken, String? refreshToken}) {
    this.accessToken = accessToken;
    this.refreshToken = refreshToken;
  }
  @override
  void clear() { accessToken = null; refreshToken = null; }
}

Future<void> main() async {
  final tokens = Tokens();
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')),
      plugins: [DiomanAuth(tokenManager: tokens, onRefresh: (store, result) async { store.setTokens(accessToken: 'renewed'); }, onAccessExpired: (store, result) { store.clear(); })]);
  try {
    final result = await api.send<dynamic>('GET', '/items',
        call: DiomanCall(options: {DiomanAuth.option: false}));
    print(result.kind);
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

  try {
    final result = await api.send<dynamic>('GET', '/items',
        call: DiomanCall(options: {DiomanShare.option: DiomanSharePolicy.start}));
    print(result.kind);
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

### Cache

Enable Cache per call with a Duration TTL. It uses memo by default and stores successful GET/HEAD results. Use clear to invalidate all in-flight writes, or remove to invalidate just one key.

Options: `persist, cachePolicy, expires, clone, maxEntries, shouldCache, shouldStore, clock`. Full parameters and defaults: [plugin spec](docs/design/pipeline-plugin-spec.md).

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')),
      plugins: [const DiomanCache()]);
  try {
    final result = await api.send<dynamic>('GET', '/items',
        call: DiomanCall(options: {DiomanCache.option: const Duration(minutes: 1)}));
    print(result.kind);
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

### Offline

Offline waits inside cache, so a cache hit can still answer while the network is down. The queue holds 50 calls by default and evicts the oldest on overflow; a nonpositive capacity removes the limit. Return false from shouldQueue to send immediately.

Options: `isOnline, onConnectivityChanged, shouldQueue, maxQueueSize, maxWait`. Full parameters and defaults: [plugin spec](docs/design/pipeline-plugin-spec.md).

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')),
      plugins: [DiomanOffline(isOnline: () => true, onConnectivityChanged: const Stream<bool>.empty())]);
  try {
    final result = await api.send<dynamic>('GET', '/items',
        call: DiomanCall(options: {DiomanOffline.option: const DiomanOfflineOptions(maxWait: Duration(seconds: 10))}));
    print(result.kind);
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

## Environment

Use DiomanEnvs to apply environment configuration during setup. It merges the first matching EnvRule into BaseOptions, without a request option or a place in the request chain. Ejecting it leaves the applied configuration in place.

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(), plugins: [
    DiomanEnvs([EnvRule(rule: () => true, config: BaseOptions(baseUrl: 'https://api.example.com'))]),
  ]);
  print(api.inspect());
  api.dispose();
  api.dio.close(force: true);
}
```

## Custom plugins

Keep configuration in DiomanPlugin and let the DiomanPluginInstance returned by setup hold each client’s state. Within a stage, use pre to run before built-ins or post to run after them; ties retain registration order.

Calling next(patch) derives a request from the current baseline without changing sibling attempts. StateKey uses identity, so create a non-const instance. Use ctx.wait for waits and check ctx.cancelled() after awaiting. Before sending more than once, call markReplayable. Map/List/FormData bodies are cloned on demand; single-subscription Streams cannot be guaranteed replayable.

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';
class Trace extends DiomanPlugin<DiomanResponse<dynamic>> {
  const Trace();
  @override
  String get name => 'app:trace';
  @override
  DiomanStage get stage => DiomanStage.prepare;
  @override
  DiomanEnforce get enforce => DiomanEnforce.pre;
  @override
  DiomanPluginInstance<DiomanResponse<dynamic>> setup(
      Dioman<DiomanResponse<dynamic>> client) => _Trace();
}
class _Trace extends DiomanPluginInstance<DiomanResponse<dynamic>> {
  final visits = StateKey<int>('visits');
  @override
  Future<DiomanResponse<dynamic>> handle(
      DiomanContext<DiomanResponse<dynamic>> ctx,
      DiomanNext<DiomanResponse<dynamic>> next) async {
    ctx.set(visits, (ctx.get(visits) ?? 0) + 1);
    await ctx.wait(Future<bool>.value(true));
    final cancelled = ctx.cancelled();
    if (cancelled != null) return cancelled;
    return next(const RequestPatch(headers: {'X-Trace': 'demo'}));
  }
}

void main() {
  final api = Dioman(dio: Dio(), plugins: [const Trace()]);
  print(api.inspect());
  api.dispose();
  api.dio.close(force: true);
}
```

# 从 0.7.2 迁移到洋葱管线

## 安装方式

将安装到 Dio 的拦截器改为持有 Dioman 客户端。裸调 Dio 不经过管线。动态安装用 use，移除用 eject，查看顺序用 inspect；extend 重新 setup，不共享插件状态。dispose 不关闭调用方持有的 Dio。

旧写法（仅供识别，不参与编译）：

<!-- docs:old -->
```dart
final handle = Dioman.install(dio, plugins: plugins);
final response = await dio.get("/users");
```

新写法：

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')),
      plugins: [const DiomanRepath(), const DiomanFilter(), const DiomanCache()]);
  try {
    final data = await api.get<Map<String, dynamic>>('/users/{id}',
        query: {'id': 42},
        call: DiomanCall(options: {DiomanCache.option: const Duration(minutes: 1)}));
    print(data);
    final result = await api.send<dynamic>('GET', '/health');
    print('${result.kind.name}: ${result.status} / ${result.httpStatus}');
  } on DiomanResponse catch (failure) {
    print('${failure.kind.name}: ${failure.message}');
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

行为差异：

- 通过 api 发起逻辑请求；底层 Dio 的拦截器仍负责实际传输。
- 固定阶段决定执行顺序，重复插件名在构造或 use 时拒绝；不再手工 sort/validate。
- use/eject/inspect 管理当前客户端，extend 重新 setup 独立状态；dispose 不关闭调用方的 Dio。

## 请求与结果

动词方法返回 data；send 返回完整结果。query 替代 Dio 调用的 queryParameters；请求配置使用 DiomanCall。key/cancel/normalize/log 无需安装：分别使用 DiomanKeyOptions、cancelAll/pending、DiomanResponseFactory、debug 或 Dio LogInterceptor。显式 key 字符串覆盖自动键，false 同时禁用 cache/share。envelope=false 保留原数据；silent=true 抑制默认通知。

旧写法：

<!-- docs:old -->
```dart
final response = await dio.get('/items', queryParameters: {'page': 1},
    options: Options(extra: {'dioman:retry': 2}));
print(response.data);
```

新写法：

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio());
  try {
    final data = await api.get<List<dynamic>>('/items', query: {'page': 1},
        call: DiomanCall(options: {DiomanRetry.option: 2}));
    print(data);
    final result = await api.send<dynamic>('GET', '/items');
    print(result.status);
  } finally {
    api.dispose();
    api.dio.close(force: true);
  }
}
```

行为差异：

- 动词方法直接返回 data；需要状态、原因和原始响应时使用 send。
- extra 不再承载插件配置；key、silent、envelope 和 options 都放在 DiomanCall。

## 错误处理

捕获 DiomanResponse，按 kind 与 reason 分流；不要再捕获旧异常子类。status 是逻辑状态，httpStatus 是 HTTP 状态。send 对可预期失败返回结果，但程序错误仍原样抛出。判定回调的错误不吞掉；通知回调错误隔离，onRefresh 抛错算刷新失败。

旧写法：

<!-- docs:old -->
```dart
try {
  await dio.get('/items');
} on DioException catch (error) {
  if (error.error is DiomanException) print(error.error);
}
```

新写法：

```dart
import 'package:dio/dio.dart';
import 'package:dioman/dioman.dart';

Future<void> main() async {
  final api = Dioman(dio: Dio(BaseOptions(baseUrl: 'https://api.example.com')));
  try {
    final r = await api.send<dynamic>('GET', '/items',
        call: const DiomanCall(key: false, envelope: false, silent: true));
    if (!r.ok && r.kind == DiomanKind.offline) print(r.reason);
  } finally { api.dispose(); api.dio.close(force: true); }
}
```

行为差异：

- 动词方法失败时抛 DiomanResponse；send 返回失败结果，程序错误仍抛出。
- 业务状态与 HTTP 状态分别查看 status/httpStatus，失败类别与具体原因分别查看 kind/reason。

# dioman 架构概览

Dioman 是以 Dio 为引擎的请求包装器。客户端编译插件链，每次逻辑调用捕获链快照；Dio 拦截器在真正传输时运行。使用入口是 lib/dioman.dart 的 show 白名单。

## 请求流

outer（loading、notify）→ prepare（repath、filter、timeout）→ attempt（retry、breaker）→ credential（auth）→ source（mock、share、cache、offline）→ Dio → 归一化结果沿链返回。

envs 只执行 setup。自定义插件在指定阶段按 pre/post 排序；同组稳定排序。配置属于工厂，状态属于每客户端 setup 实例。请求补丁从当前基准派生，兄弟尝试互不污染。

## 内核边界

key 在整形后惰性计算；取消覆盖整个逻辑请求；等待统一清理计时器和订阅。响应工厂只拆一层信封，kind、逻辑状态与 HTTP 状态分开。链内返回结果，公共边界将程序错误原栈抛出；动词方法对可预期失败抛结果，send 返回结果。

## 模块与贡献入口

## 交错性能

固定 A=895d959，B=当前实现；每次独立 JIT 进程，S1–S6 各预热 500ms、正式至少 2s，发送数自检未修改。每组为 A1 B1 A2 B2 A3 B3，完成 **2 组**，没有挑轮拼指标。最初另有一次 A/B 尝试在读取新版输出前导换页字符时解析中断；原始数据以 initial-bench-* 保留，不计入三轮。修正仅为 strip 空白，随后完整重跑。两个完整组的旧版临时 worktree 均由 finally 删除，最终 worktree 列表无 bench 项。

环境：Dart 3.13.0 stable、Windows 10 Pro 19045、20 个逻辑处理器、JIT；包 SDK 约束不变。首组执行时有文档验证活动，第二组暂停本任务的分析/测试进程后完整重跑；没有控制其它进程、CPU 频率或系统调度，主会话另确认其它会话负载、CPU 约 37%，本次按要求保留数据，等待空闲复测。

### 简单 profiling 与建议

VM service 采样实验返回 0 CPU 样本，见 profile-summary.json 与压缩原始结果；不能据此声称任何函数是 CPU 热点。随后通过公开插件 API 在每阶段 pre/post 插入 Stopwatch 探针，1000 次预热后测 5000 次全插件缓存未命中。该实验单独运行，不混入交错结果。

[阶段计时](pipeline-b6-evidence/profile-timers.json)：outer 10.58μs、prepare 22.12μs、attempt 9.14μs、credential 8.50μs、source 99.05μs；最内层 Dio+归一化 154.70μs，最外层总计 307.10μs。阶段差含探针本身成本，且会受调度影响，只能定位“来源层”和“传输/归一化”两个较大的区段，不能细分为具体函数的 CPU 归因。

供终审选择：下一轮分别隔离构键、cache 快照和 share 等待注册，检查未命中路径的 Map/闭包/Future 分配；另量化 Dio RequestOptions 转换与响应工厂分配。S2 则优先单独测客户端上下文、取消桥与请求配置成本。上述都是待验证的优化方向，本批未修改库代码，也未以探针结果证明优化收益。

  good,

  poor,

/// 某档的超时；null 保留请求已有值。
class DiomanTimeouts {
  /// [connect]、[receive]、[send] 分别覆盖三个 Dio 超时，例如 `DiomanTimeouts(receive: Duration(seconds: 2))`。
  const DiomanTimeouts({this.connect, this.receive, this.send});

  /// 连接超时。
  final Duration? connect;

  /// 接收超时。
  final Duration? receive;

  /// 发送超时。
  final Duration? send;
}

/// 请求级超时配置，按档位取并集，单档整体替换。
class DiomanTimeoutOptions {
  /// [enabled] 为 false 时保留原配置，[timeouts] 只覆盖列出的档位。
  const DiomanTimeoutOptions({this.enabled, this.timeouts});

  /// 本次开关。
  final bool? enabled;

  /// 本次覆盖的档位。
  final Map<NetworkQuality, DiomanTimeouts>? timeouts;
}

/// 通过 next(patch) 写超时字段，实际计时交给 Dio。
class DiomanTimeout<R extends DiomanResponse<dynamic>> extends DiomanPlugin<R> {
  /// [probe] 每请求同步求值一次，例如 `DiomanTimeout(probe: () => NetworkQuality.good)`。
  const DiomanTimeout(
      {required this.probe,
      this.timeouts = defaultTimeouts,
      this.enabled = true});

  /// 当前档位提供器，抛错按 bug 原样落定。
  final NetworkQuality Function() probe;

  /// 档位配置。
  final Map<NetworkQuality, DiomanTimeouts> timeouts;

  /// 安装期开关。
  @override
  final bool enabled;

  /// 稳定名称。
  static const pluginName = 'dioman:timeout';

  /// 请求级 bool 或 DiomanTimeoutOptions 键。
  static final option = DiomanOptionKey<DiomanTimeoutOptions>(pluginName);

  /// excellent 与 none 的默认连接时长。
  static const defaultConnect = Duration(seconds: 10);

  /// 旧版默认值：仅写连接超时。
  static const defaultTimeouts = {
    NetworkQuality.excellent: DiomanTimeouts(connect: defaultConnect),
    NetworkQuality.good: DiomanTimeouts(connect: Duration(seconds: 15)),
    NetworkQuality.poor: DiomanTimeouts(connect: Duration(seconds: 30)),
    NetworkQuality.none: DiomanTimeouts(connect: defaultConnect),
  };

  /// 返回稳定名称。
  @override
  String get name => pluginName;

  /// 请求整形阶段。
  @override
  DiomanStage get stage => DiomanStage.prepare;

  /// 复制配置映射，实例不共享可变状态。
  @override
  DiomanPluginInstance<R> setup(Dioman<R> client) =>
      _Timeout<R>(probe, DiomanTimeoutOptions(timeouts: Map.of(timeouts)));
}

/// 每客户端的预合并配置。
class _Timeout<R extends DiomanResponse<dynamic>>
    extends DiomanPluginInstance<R> {
  /// 保存配置与档位回调。
  _Timeout(this.probe, this.base);

  /// 档位回调。
  final NetworkQuality Function() probe;

  /// 基础配置。
  final DiomanTimeoutOptions base;

  /// 缺档直接放行；null 字段保持原值。
  @override
  Future<DiomanResponse<dynamic>> handle(
      DiomanContext<R> ctx, DiomanNext<R> next) {
    final o = resolveOption<DiomanTimeoutOptions>(
        ctx.request.call.options[DiomanTimeout.option],
        base: base,
        merge: (a, b) => DiomanTimeoutOptions(
            enabled: b.enabled, timeouts: {...a.timeouts!, ...?b.timeouts}));
    if (o == null || o.enabled == false) return next();
    final t = o.timeouts![probe()];
    if (t == null) return next();
    return next(RequestPatch(
        connectTimeout: t.connect ?? ctx.request.connectTimeout,
        receiveTimeout: t.receive ?? ctx.request.receiveTimeout,
        sendTimeout: t.send ?? ctx.request.sendTimeout));
  }
}

class _Mock<R extends DiomanResponse<dynamic>> extends DiomanPluginInstance<R> {
  /// 保存预合并配置。
  _Mock(this.base);

  /// 插件配置。
  final DiomanMockOptions base;

  /// 探测状态只包围一次 next，回落恢复共享与缓存。
  @override
  Future<DiomanResponse<dynamic>> handle(
      DiomanContext<R> ctx, DiomanNext<R> next) async {
    final o = resolveOption<DiomanMockOptions>(
        ctx.request.call.options[DiomanMock.option],
        base: base,
        merge: (a, b) => DiomanMockOptions(
            enabled: b.enabled,
            routes: {...a.routes!, ...?b.routes},
            mockUrl: b.mockUrl ?? a.mockUrl,
            fallbackWhen: b.fallbackWhen ?? a.fallbackWhen));
    if (o == null || o.enabled == false) return next();
    final cancelled = ctx.cancelled();
    if (cancelled != null) return cancelled;
    final route = o.routes!['${ctx.request.method}:${ctx.request.uri.path}'];
    if (route != null) {
      final data = await ctx.wait(Future.sync(() => route(ctx.request)));
      return ctx.cancelled() ??
          ctx.factory.normalize(ctx.request,
              raw: data is Response<dynamic>
                  ? data
                  : Response<dynamic>(
                      requestOptions: ctx.request.toRequestOptions(),
                      statusCode: 200,
                      data: data));
    }
    final url = o.mockUrl;
    if (url == null || url.isEmpty) {
      ctx.log('[mock] 缺少 mockUrl，跳过探测');
      return next();
    }
    ctx.markReplayable();
    late DiomanResponse<dynamic> probe;
    ctx.set(sourceProbe, true);
    try {
      final path = ctx.request.uri.path;
      final original = Uri.parse(ctx.request.path);
      final query = original.hasQuery ? '?${original.query}' : '';
      probe = await next(RequestPatch(
          path: '${url.replaceFirst(RegExp(r'/+$'), '')}$path$query'));
    } finally {
      ctx.set(sourceProbe, false);
    }
    final cancel = ctx.cancelled();
    if (cancel != null) return cancel;
    final fallback = o.fallbackWhen?.call(probe) ??
        (probe.httpStatus == 404 || probe.kind == DiomanKind.network);
    return fallback ? next() : probe;
  }
