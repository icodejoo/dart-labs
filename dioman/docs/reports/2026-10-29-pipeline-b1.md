## 规格不清与保守取舍

### 需要终审确认

1. **泛型工厂失败回退的返回类型**：Dart 无法让内置基础响应实例满足任意用户子类 R，同时保证工厂自身抛错后 next 不抛 TypeError。因此链、`ctx.fail`、中间件 handle/next 的实际响应返回类型为 `DiomanResponse<dynamic>`，R 约束客户端正常工厂的 create 返回类型。坏工厂回退基础 internal 并保留首次异常，优先满足 D4/D6 的收尾与原错落定；未做不安全的 `as R` 回退。与架构伪代码的 `Future<R>` 有签名差异，需终审认可或另定结果联合类型。
2. **请求体的不可变范围**：请求视图及有效元数据快照不可修改，headers/query/extra 为不可修改的顶层集合；data 作为 Dio 的不透明载荷保留引用。JSON、FormData、Stream 并非统一可深冻结，且旧 key 对非 Map 载荷使用对象身份。依据 P4，仅 markReplayable 时复制 Map/List/FormData；普通发送不预复制。插件修改载荷的契约为 next(patch)，而非原地写 data。若要求任意嵌套 data 在运行时强制不可变，需要另外裁决身份 key、性能和 Dio Transformer 的兼容方式。
3. **send<T> 的数据与扩展**：失败数据允许 null，因此 `DiomanResponse<D>.data` 为 D?。返回结果已是 `DiomanResponse<T>` 时保留原实例及扩展字段；否则物化为基础的类型化响应，失败 data 与 T 不兼容则为 null，原值仍在 raw。自定义工厂应返回与调用数据类型匹配的泛型子类；已验证成功、debug 失败和 reject 的扩展字段。任意 R 与任意 T 的组合不能同时保证静态数据类型和任意子类身份，需要终审确认此边界。

### 已按规格处理

- 替换 cancelToken 的派生上下文只受替换令牌控制；逻辑请求状态仍共享，根取消不会把共享传输当作已取消。最外层调用者最终仍按自己的逻辑令牌落定。该行为用于 B4 share，已有隔离回归。
- Dio 没有 Future 退订接口，桥对象本身可保留在用户 token 上，但结局后桥的目标被清空，不再持有请求服务；内核等待订阅、计时器和 pending 均清理。不把不可退订的 Dio Future 声称为物理移除。
- extend 按规格克隆 BaseOptions 容器并重新 setup 插件，创建新 Dio；没有替使用者复制拦截器或共享 adapter 生命周期。
- Dio 5.11 新增而规则表未列的 transformTimeout 走默认 internal；不扩大既定 timeout 三种类型，也不提高 Dio 最低版本。
- StateKey 保留 const 构造；需要同描述仍独立的键时使用非 const 实例。DiomanOptionKey 按身份使用静态 final 实例。
