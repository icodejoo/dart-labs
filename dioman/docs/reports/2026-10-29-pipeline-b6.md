## 交错性能

固定 A=895d959，B=当前实现；每次独立 JIT 进程，S1–S6 各预热 500ms、正式至少 2s，发送数自检未修改。每组为 A1 B1 A2 B2 A3 B3，完成 **2 组**，没有挑轮拼指标。最初另有一次 A/B 尝试在读取新版输出前导换页字符时解析中断；原始数据以 initial-bench-* 保留，不计入三轮。修正仅为 strip 空白，随后完整重跑。两个完整组的旧版临时 worktree 均由 finally 删除，最终 worktree 列表无 bench 项。

环境：Dart 3.13.0 stable、Windows 10 Pro 19045、20 个逻辑处理器、JIT；包 SDK 约束不变。首组执行时有文档验证活动，第二组暂停本任务的分析/测试进程后完整重跑；没有控制其它进程、CPU 频率或系统调度，主会话另确认其它会话负载、CPU 约 37%，本次按要求保留数据，等待空闲复测。

表中每实现按 ops/s 中位数所在轮取完整行；括号为三轮吞吐极差 `(max/min-1)×100%`。S5 单位为 **100 请求整组/秒**，其它为请求/秒。延迟为同一中位轮的 mean / p99，单位 μs。所有极差均 ≥10%，所以全部标记为待复测。两组方向一致：S2 无插件新版绝对吞吐约低 20–30%（中位数分别低 29.3% 和 20.4%），S3–S6 新版更高。这里记录观察，不下通过/不通过结论。

### 门槛逐项结论

| 门槛（原值不变） | 结论 |
|---|---|
| S2 无插件额外开销 ≤ 旧版无插件额外开销 | **不下结论**。S1/S2 都不稳定；旧 S2 有轮次快于自身 S1，不能据此构造可靠的比例开销基线 |
| S3 全插件未命中额外开销降低 ≥20% | **不下结论**。S1/S3 均不稳定，不能用表面吞吐差宣称满足 20% |
| S4 缓存命中不低于旧版 | **不下结论**。两组双方三轮极差均超标 |
| S5 100 并发共享不低于旧版 | **不下结论**。两组双方三轮极差均超标，单位始终为组/秒 |
| S6 POST + retry 不触发不低于旧版 | **不下结论**。两组双方三轮极差均超标 |

S2/S3 只有在 S1 与目标场景都稳定后才可比较同一轮 `mean(Sn)/mean(S1)-1` 的比例开销；本批没有直接用不同时段裸 Dio 绝对值相减、改变门槛、或把不稳定样本判作通过。性能验收仍需终审安排可控负载下复验。

### 简单 profiling 与建议

VM service 采样实验返回 0 CPU 样本，见 profile-summary.json 与压缩原始结果；不能据此声称任何函数是 CPU 热点。随后通过公开插件 API 在每阶段 pre/post 插入 Stopwatch 探针，1000 次预热后测 5000 次全插件缓存未命中。该实验单独运行，不混入交错结果。

[阶段计时](pipeline-b6-evidence/profile-timers.json)：outer 10.58μs、prepare 22.12μs、attempt 9.14μs、credential 8.50μs、source 99.05μs；最内层 Dio+归一化 154.70μs，最外层总计 307.10μs。阶段差含探针本身成本，且会受调度影响，只能定位“来源层”和“传输/归一化”两个较大的区段，不能细分为具体函数的 CPU 归因。

供终审选择：下一轮分别隔离构键、cache 快照和 share 等待注册，检查未命中路径的 Map/闭包/Future 分配；另量化 Dio RequestOptions 转换与响应工厂分配。S2 则优先单独测客户端上下文、取消桥与请求配置成本。上述都是待验证的优化方向，本批未修改库代码，也未以探针结果证明优化收益。
