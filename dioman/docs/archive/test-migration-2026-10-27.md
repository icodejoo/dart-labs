## 去重与补回

- **撤销的合并**：上一个执行者（Codex）把 5 条用例当"重复"并入了别的用例。逐条对照原文后，按 §3.2「同 id 不同输入是变体，保留」判定**都不是重复**（接线方式 / 并发时序 / 档位 / 调用方数不同），已从原文补回：
  1. `pairwise: share + retry` > `FIX: a THIRD caller …`（用 `retry.share` 兼容 setter 接线；与自动接线那条输入不同）→ `combo/retry_share_recovery_combo_test.dart`
  2. `pairwise: cancel + auth` > `without any manual wiring, cancelAll …`（无手动接线；保留的那条用 `..cancel = cancel`）→ `combo/auth_cancel_combo_test.dart`
  3. `DiomanShare` > `policy=end: every caller …`（并发直发，不加闸门）→ `rule/share_rule_test.dart`
  4. `DiomanTimeout` > `per-request timeouts merge …`（覆盖 poor 档；保留的那条覆盖 good 档）→ `rule/timeout_rule_test.dart`
  5. `DiomanShare policy: race` > `only once every in-flight attempt has failed …`（单调用方）→ `rule/share_rule_test.dart`
- **唯一的 drop**：`dioman_combinations_test` 的 `pairwise: cancel + retry`，是 `() {}` + `skip:` 的空体占位，注释自己写明"真正的回归用例在 dioman_test.dart"，保留者是 `combo/cancel_retry_combo_test.dart` 里 `a token this plugin injected stays trackable by cancelAll() …`。
- 其余同文件/同插件内相似度 ≥0.8 的用例对都复核过：输入（策略、状态码、接线方式、是否并发）或断言不同，按变体保留。没有因"看起来像"就删的。
- 变体多时合并成参数化循环属于"先搬后改"之外的改动，本次没做；有候选的是 share 的 end/race 同构用例、cache 的 clone 策略，另起提交处理。

## 保真说明

- 用例代码体取自上一个执行者重构后的版本：测试辅助（6 份同义 token 实现等）已合并到 `test/support/fixtures.dart`，重复字符串已提取为 `test/accept/lib/literals.dart` 常量（`tk*`）。本次**没有逐行回溯原文**核对这些重构。
- 用来兜底的证据：334 条旧用例名与 333 条新用例名**一一对应**（脚本按"去掉 `[API id]` 前缀后名字相等"匹配，旧侧 0 个未匹配、新侧 0 个多余）；默认运行 330 全过；lcov 行覆盖与基线同为 1788/1793。
- 补回的 5 条用例是从 `coverage/reorganization/original-test/` 原文移植的，只把本地 helper 换成 fixtures 里的同名夹具、把已登记的重复字符串换成常量。

## 层归属上的几处判断

- `extra_keys`：注册表本身的内容/登记/注销 → unit；扫描 `lib/src` 源码、核对 `ARCHITECTURE.md` 键表、重复实例诊断（要 `Dioman.install`）→ integration。
- `plugin_order`：`Dioman.sort/validate` 是纯函数 → unit；`Dioman.install` 的顺序、`DiomanHandle.insert*/remove` 动态插拔 → integration（与 install 合进 `install_integration_test.dart`）。
- `replay_support` / `request_claims`：库内部基础设施，没有台账 id，标题用 `[模块.函数]`。
- pairwise 生成器是 unit（`[binaryPairs]`）。**pairwise 扫描本身没有 `test/` 里的用例**，只在 `accept/`（5 方法矩阵）里跑，所以没有 `pairwise_combo_test.dart`。
- 真实服务的 3 个入口放 integration + `@Tags(['real'])`，原 `DIOMAN_ACCEPT*` 环境变量门控去掉（默认由标签排除，`-t real` 才跑）；它们是白盒入口，真正的黑盒场景仍在 testkit，所以 mirror 列留空。
