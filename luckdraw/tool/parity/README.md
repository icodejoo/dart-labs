# lucky-canvas 1:1 对照基线生成

本目录在本机 Chrome 中运行 npm 的 `lucky-canvas@1.7.26`，记录原始数值和
Canvas PNG；Flutter 对照位于 `test/parity/`。DIAG 已完成 Windows 图像差异
分类，仅 w04/60 允许文字分层容差；F2 已解除 s01/s02/s04 与 g05 的 skip，
DIAG2 保留 s03/s05 的 golden skip，具体见文末的十帧复诊。
跨平台容差仍待对应环境实测。

## 运行

从 `luckdraw/` 运行；Dart 3.5 及以上，不需要 Node、npm、Puppeteer 或任何新增依赖：

```powershell
dart run tool/parity/generate.dart
dart run tool/parity/generate.dart --verify-manifest
flutter test test/tool/parity_generate_test.dart --no-pub --concurrency=1
```

生成需要系统 `curl`、`tar`、Chrome 和 Flutter SDK 的 Roboto Regular TTF。
SHA-256 用 Windows `certutil` 或 Linux `sha256sum`。生成器只 import `dart:io`
和本目录的 `codec.dart`；后者是无 import 的 JSON / PNG base64 编解码纯函数，
自测使用 SDK `dart:convert` 作为独立参照。没有新增 pubspec 依赖。

Chrome 查找顺序为 `--chrome=路径`、`CHROME_PATH`、常见安装目录和
`where chrome.exe` / `which google-chrome`。字体从 `--font=路径`、
`FLUTTER_ROOT` 或 Dart SDK 的上级 Flutter SDK 查找。例如：

```powershell
dart run tool/parity/generate.dart --chrome="C:/Program Files/Google/Chrome/Application/chrome.exe" --font="E:/sdk/flutter/bin/cache/artifacts/material_fonts/roboto-regular.ttf"
```

`--root=目录` 可选择具有相同 `tool/parity/` 目录结构的工作目录，用于仓库外调试。
Windows Chrome 的版本从该 exe 的 `ProductVersion` 读取；Windows 的
`chrome --version` 不能可靠返回标准输出，且可能打开用户的浏览器。
Linux 使用 `chrome --version`。

下载与解包位于系统临时目录 `luckdraw_parity/`，不在上游源码目录构建。
首先用 curl 下载 npm registry 的固定 tarball；下载失败时尝试 npmmirror。
每次生成都校验下载物 SHA-256：

```text
d3bcd87eba14ddf88896b6872db5a9196f95e1e94df7da87069d671ddfecd670
```

所有 Chrome 调用串行执行，使用 `--headless=new --dump-dom` 和独立临时
`--user-data-dir`，通过页面的 `<pre id="out">` 传递数值和 PNG data URL。
单个外部命令超时为两分钟；超时只结束本次启动的 PID 及子进程。
正常退出后删除本次 run 目录，保留下载缓存。用户的 Chrome 不受影响。
全部用例验证成功后才复制生成物，最后写 MANIFEST；失败退出码为 1。

`--verify-manifest` 完全离线，不启动 Chrome，也不查找字体。它校验：
固定的上游版本 / tarball / 参照提交 / 16ms 时间基准、完整来源信息、
16 个配置文件摘要、96 个数值或 PNG 产物的摘要、PNG 签名，以及帧序列结构。
任何配置或产物缺失、修改或清单过期都失败。CI 运行这个命令即可。

## 用例与时钟契约

用例对应 TEST_STRATEGY §6.2 的全部 16 行：w01–w06、g01–g05、s01–s05。
逻辑尺寸 180×180，DPR 1；每例记录 420 帧、5 张关键帧 PNG。
所有文案为 ASCII；上游实际使用 `fontStyle` 表示字体族，配置中明确设为
`Roboto`、400 字重并加载与 Flutter 测试相同的 SDK TTF。w04 的图片是内嵌
8×8 PNG，没有远程图片或系统字体依赖。

伪时钟遵循 TEST_STRATEGY §6.3：

1. 字体和上游每个真实 `loadImg` promise 全部完成后开始采样。不能仅依赖
   上游 `afterInit`，因为它可能早于其它图片完成（U-22）。
2. `Date.now()` 返回伪时间；`requestAnimationFrame` 只排队；`Math.random`
   顺序消费 JSON 的 `random[]`，耗尽立即失败，不循环。
3. 第 0 帧在 T=0 执行脚本的 `play()`，它同步 `run(0)`。本帧不再消费 rAF。
   第 f>0 帧在 `T=16*f` 先执行脚本，再只消费一个已排队 rAF。
   新回调留给下一帧。结束后继续记录静止值直到 420 帧，时间仍按 f 前进。
4. 转盘 `rotateDeg` 和九宫格 `currIndex` 按原值记录并强制单调不减；
   不取模、不修正上游公式。老虎机记录 `scroll[]/stopScroll[]/endScroll[]`，
   允许负余数、周期回绕以及 U-06 的减速首帧跳零。

`frames.json` 包含 `initial`（开始前快照）、`frames`（play 后逐帧快照）、
`events`（原始 end 回调帧号、时间、结果和奖品下标）、`settledFrame`、
`randomConsumed` 与 `keyframes`（标签到文件名、真实帧号、时间的映射）。
上游 `run(0)` 的 FPS 为 `0/0`，以 null 表示；其它运动数值必须有限。
上游 undefined 的奖品标志和回调结果也以 null 表示；取消转盘返回的 `{}`
仍保留为空对象。w02 消费两个随机数（加权选奖、stopRange）。

关键帧 0 是 **play 前**画面；数值帧 0 是同步 `run(0)` 后状态，九宫格此时
`currIndex=0.1`。其它固定关键帧在本帧推进后截图。`kf_settled.png` 使用
第一次 step=0 的画面，包含取消路径。`events` 保留未经归一化的上游帧号：
正常结束的 end 回调比 settledFrame 晚一帧（DEV-06），Flutter 比较时再减 1。
取消 w06 的 end 发生在 stop 当帧排队的回调中；s05 完全没有 end。

## 文档差异与保守处理

- T4.3 的简述提到动作后立即 `+16` 消费 rAF，若在第 0 帧照做，会多推进一次。
  本批按更精确的 TEST_STRATEGY §6.3 和任务要求，`play()` 的同步 `run(0)`
  单独作为数值帧 0。建议 T4.3 改为上述明确的 f=0 / f>0 规则。
- §6.2 示例 stop frame=120 对应 1920ms，小于默认加速时间 2500ms。
  标注匀速停止的用例使用第 180 帧（2880ms）；w03/g05 保持第 30 帧提前
  停止。常规关键帧为 `[0,60,170,240,"settled"]`：开始前、加速、匀速、
  减速、停止。提前停止及取消用例的阶段以数值记录为准。
- T4.3 建议 HttpClient 下载；本批用户明确要求 curl，按用户指令执行。
- T4.3 未规定生成器自测名称；本批以 `parity generate > …` 命名 10 条工具
  自测并登记 R4-06 与 B12a 补充行。任务卡中所有 Flutter parity 测试留到后续。

## npm 产物与给定 TS 的首次抽查

参照提交按设计文档记录为 `7a8c0bbcb992a297b390e3a2ebaa1a3385c1f2f9`。
检查实际下载的 `dist/index.umd.js` 中三个刻舟求剑函数的执行顺序，并利用
同 tarball 的 UMD sourcemap 对照用户提供的只读 TS 文件，结果如下：

| 函数 | 对照结论 |
| --- | --- |
| wheel.ts `carveOnGunwaleOfAMovingBoat` | 函数文本一致；候选角度和最近首帧速度选择次序一致 |
| grid.ts `carveOnGunwaleOfAMovingBoat` | 函数文本一致；候选格序和最近首帧速度选择次序一致 |
| utils/index.ts `computeRange` | 函数文本一致；正权重累加、NaN 洞、`random * sum` 与 `<=` 选择一致 |
| utils/index.ts `splitText` | 函数文本一致；逐字符测量、预留省略号和 lineClamp 返回规则一致 |
| slot.ts `carveOnGunwaleOfAMovingBoat` | 有一行差异：npm 使用 `slot.order!`，给定 TS 使用 `slot.order || this.defaultOrder`；候选位移、绝对首帧速度阈值与首个超阈值选择相同 |

npm 的 `initSlot()`（sourcemap slot.ts:277–285）在绘制前执行
`slot.order = slot.order || defaultOrder`，所以本批非空、有效 order 的五个
老虎机用例两种写法等价。s01 仍在 JSON 中省略 order，真实覆盖 npm 的默认
补齐行为；s02 使用各列不同的显式 order。本批保持 npm 产物原样，不复制上游
源码进包、不自行改设计。后续 Flutter 对照必须保留这一差异记录，不能声称
整个 npm 文件与参照 TS 完全相同。

## 容差（DIAG 证据校准，优先于上文 B10b 的待判定状态）

## DIAG 最终判定（2026-11-10，覆盖 B10b 的待判定状态）

**混合情形：只解除 w04 golden 的 skip。s01–s05 保留 skip 和原容差，g05 数值测试仍跳过；不改 lib、既有基线或 MANIFEST。**

- w04/60：670 个差异像素（2.067901235%，RGBA 均误 1.368225309），**100% 位于每行文字矩形外扩 2px 内**；图片/形状/阴影/其它均 0%。去文字五帧差异像素均为 0，最大均误 0.040270062。文字 x、y、宽度没有系统性偏移，符合 DEV-01 的文字光栅化差异。
- text-heavy **仅允许 `(w04, '60')`**，通道阈值仍为 32。按该帧实测值乘 1.1，实际限值为 **2.274691358% / 1.505047840**，低于用户允许的 4.0% / 2.5 总上限；其余全部帧仍为 1.8% / 1.8。没有把 w04 整例或其它老虎机帧加入宽容差。
- 五个老虎机超限帧的文字占比仅 **35.0394%–68.3131%**（全部五帧含通过的 60 帧为 35.0394%–68.3131%），均不满足 95% 门槛；形状区域为 31.6869%–64.9606%。s02/60 去文字仍为 **603/32400 = 1.861111111% / 0.855648148**，超过 1.8%。判为**疑似几何/接缝绘制缺陷**，不能按纯文字差异接受。
- 六例均为 Roboto ASCII；最差帧宽度误差为 0，老虎机变换后的基线/起点误差 ≤2.85e-14px，转盘变换误差 ≤2.51e-6px（Canvas2D 变换精度）。空格与实际行的 TextPainter 字母基线差为 0；本组**未复现 R1-03 回退字体下移**。此结论不代替 F1 的回退字体修复。

完整报告及可复查原始数据：用户指定 scratchpad/reviews/parity_diag.md；同级 parity_diag/ 内含 regions.json、notext.json、coordinates.json、Chrome 原始 fillText/measureText/drawImage 记录、Flutter 逐行布局、预乘 RGBA 和 160 张差异/并排 PNG。原图与去文字各 40 帧（6 个目标用例 + w01/g01 对照，每例 5 帧）。

诊断命令参数：标准生成器的 `--root=<临时目录>/notext`，不向仓库 cases、baselines 或 MANIFEST 添加变体。variant 仅移除 fonts/texts。报告目录的脚本与参数可复现区域采样；160 张掩码/并排 PNG 保留在用户指定外部报告目录。

正式每帧由 parityImageTolerance 选择 LuckyToleranceComparator；最终 metrics 的断言也使用同一白名单。新增两条回归测试逐一核验 16×5 帧的白名单及实测10%余量，避免未来把整个用例或所有老虎机放宽。

正常运行仍为 `flutter test test/parity --no-pub --concurrency=1`。强制图像审计可加 `--dart-define=PARITY_AUDIT=true --plain-name 'keyframes match upstream within tolerance'`：当前五个老虎机预期失败、w04 通过；不要把全量审计当作通过门禁。g05 第157帧的公开阶段问题详见 FINDINGS.md，本批不改 lib。
