# 静态 SVG 合并绘制与分帧录制

## 结论

分帧把两张最重图的单帧录制峰值约从 242–277 ms 降到 21–22 ms。两张图的录制总量、首次快照和完整显示耗时均上升，转圈场景也漏掉更多节拍。合并减少路径和载荷，尚未实现同时降低录制总量与首次 raster 成本的目标。

## 实现

- **Rust** 只考虑同一个 usvg 分组内相邻的单轮廓、闭合、轴对齐实色不透明矩形。颜色和填充规则相等、两两边界严格分离才拼接 verb 和 point。图片和子组切断当前合并。描边、渐变、图案、遮罩、模糊与半透明逐条保留。分离判定把边界各外扩半个间隙，按左边界排序，只扫描可能在 X 轴上相交的前缀。每批最多 32 个矩形，逐路径工作有固定上限。
- **间隙** 是固有视口长边的 `2 / 512`。均匀缩放到长边 512 物理像素时，两张基础包围盒至少隔 2 px。小于该尺寸或非均匀缩放时，像素间隔随最终变换而变。缩放与抗锯齿实现是两个独立变量，即使物理像素互不共享，Skia 在分数像素边沿也会因原矩形与多轮廓路径采用的覆盖率计算不同产生通道差。普通斜线、圆弧和描边因此保留原来的单次调用。
- **Dart** 重场景计时预算 4 ms。在绘制或状态命令边界暂停，普通短绘制每 16 条检查时钟，长主路径每 256 个 verb 检查一次。续帧保留同一个 `PictureRecorder`、Canvas 状态栈和正在构建的 `Path`，完成后一张 Picture 原样进入现有图片坐标位图缓存。录制期间沿用冷加载占位。卸载或变更源与当前色会释放该组件对录制的引用，最后一个组件离开后取消续帧并释放临时 Picture。独立缓存请求和其它同键组件仍共用在途任务。
- **固有尺寸** 在根 SVG 同时缺少 `width`、`height`、`viewBox` 时采用 300 × 150，内容包围盒仍可大于视口。

## 方法

- Windows 在 Flutter SDK 的 Dart VM 内显式加载各版 DLL。对 714 个清单项各执行三次，按图取中位数，再在图片之间统计分位数。原生 FFI 调用计时包含 Rust 解析、显示列表构建和 SSE 编码。通过生成的解码器读出实际 SSE 字节数。有序列表存在时用其命令数，否则以路径和图片的合计计入有效命令。
- SM-A566B（`R5CY2359S7D`），Flutter 3.50.1，Android arm64 profile，Impeller Vulkan，设备目标刷新率 120 Hz。每轮采用同一顺序测量两份 APK，交替切换两版的先后次序。基准由已生成的 FRB 桥测 ②a、用 UI 侧记录钩子测 ②b、用 Embedder 时间线的 `DoMakeRasterSnapshot` 事件测 ③。
- 加载场景在 310 × 450 逻辑像素的固定容器上展示冷图，转圈保持动起来。跳转场景用相同容器及真实 Material 路由，按 Android 默认 450 ms 前进过渡窗口统计。掉帧按相邻 `vsyncStart` 间隔估计错过的节拍数。完整显示取数据交给组件到首个图稿所在帧的 raster 完成。稳态统计从首个图稿与最后一次原生快照都完成后 50 ms 开始。图标滚动冷启动加载现有 1,000 个 MDI 图标集，遍历网格滚动范围。
- RGBA 捕获使用同一个视口物理尺寸，在性能试次之后离屏执行。所有外部 SVG 与 233KB 插画由主机在运行时推送。原始测量位于 [本机忽略文件](raster_cache_auto_drawcall_raw.json)。

## 复现

按 [Android 构建参数](async_threshold_results.md#复现) 设置 NDK 28.2.13676358、CC、AR 与 linker，再分别构建 Android arm64 so 与 Windows x64 DLL。两版 APK 使用同一基准入口。旧版使用 `c78eda18` 的 Dart 库源码与旧 so，仅提供基准新增的空录制计时钩子以便同一入口编译。新版使用当前源码。构建时为每版选择相应的 `XVG_BENCH_JNI_DIR`。

```powershell
flutter build apk --profile --no-pub --android-skip-build-dependency-validation --target-platform android-arm64 -t lib/ui_thread_decode_record_main.dart
python tool/run_drawcall_merge.py --old-apk $OldApk --old-so $OldSo --new-apk $NewApk --new-so $NewSo --legacy-svg $LegacySvg
python tool/summarize_drawcall_merge.py --attach-corpus
```

PC 使用 `tool/drawcall_corpus.dart <DLL> <计划 JSON> <输出 JSONL>`。计划按语料清单顺序提供 `[{"id":"web-001","path":"<运行时文件>"}]`。两版输出在基准工程 `.dart_tool/drawcall` 下命名为 `corpus-old.jsonl` 和 `corpus-new.jsonl`。

### 结果说明

- 分帧显著压低 ②b 单帧峰值，重样本的新版典型切片在 4.03–4.05 ms。长场景的帧间等待、显示列表回放开销和不可中断的原生工作仍会抬高总量或个别帧的耗时。web-543、web-544 的单帧峰值分别降到 21.39、22.43 ms，录制总量分别升到 297.59、479.88 ms。
- 路径减少未转化成两个主样本的首次原生快照收益。web-543 从 171.32 升到 199.42 ms，web-544 从 195.81 升到 199.90 ms。两者转圈场景的首图前漏节拍及完整显示时间也上升。合并后多轮廓 Path 可能进入更昂贵的 Impeller 几何处理路径，本次没有细分出引擎内部成本。跳转窗口分别少 1 个漏节拍。完整显示时间与转圈掉帧的优化目标仍待达成。
- 千图标滚动两版的 UI 与 raster p95 持平或略降，漏节拍中位数从 5 升到 8。本轮无法确认滚动完全无回归。
- ②a 在 web-543 降到 24.54 ms，web-544 为 57.19 ms，二者依然超过 120 Hz 的 8.33 ms 帧预算。新版同组样本派发到返回分别为 76.93、89.47 ms，web-150 为 123.40 ms。派发计时包含 Flutter 送出 FRB 大字符串的开销。若继续优化重图加载，接收端分批交付值得单独测量，同时应单独分析发送端字符串搬运。
- 10 个样本的三轮 RGBA 均逐像素一致。aurora 的变化像素中位数为 3,211 / 1,103,952，最大通道差为 2。两版该样本均有 156 条路径且一次录完，差异没有随合并或切片出现。跨进程 Impeller 离屏滤镜采样波动是可能原因，现有记录无法定位到具体滤镜步骤。
- APK 内没有 SVG 素材条目。检查了 APK 资产和 AOT 库中 233KB 插画的源片段与文件名，均未发现。设备运行目录、推送中转文件和 VM Service 转发已清理，刷新率、常亮以及录制前安装的 APK 已恢复。结果中的新版 APK 早于测试补上的公开异步 Future 对象身份修复，组件渲染调用链、录制和缓存写入计时边界相同。
