# 路径合并后端自检

**结论。** Vulkan、强制 OpenGLES 各三轮均在首图后 **2.257–2.263 s** 触发，均在静止段，采集期间没有应用帧进入 raster，最大通道差均为 0。常驻 Ticker 两个后端都在约 **3.000 s** 兜底，各新增一个 raster 完成时隙缺口、零 vsync 缺口。旧「探针后」峰值主要是 Android 显示缓冲区等待。关闭探针并开启同样的 Perfetto 采集也能复现，强制合并开关在实际合并的测试图上没有表现出一致的 raster 回退。

**假设一：分批能降低帧缺口。未成立。** 上一轮 OpenGLES 单次快照的缺口为 1·1·1，三批后 vsync 为 2·2·3、raster 完成为 1·3·3，每批读回墙钟 7–21 ms。现把薄／厚矩形、细线／贴边与视口外描边、凸凹／曲线、两种填充规则、先填后描放回一张并排图。一次 `toImage`、一次预乘 RGBA 读回，Uint32 相同像素直接跳过，最大通道差超过 1 即关闭合并。

**假设二：等静止能把探针移出动画帧。成立。** 第一个达标 Picture（100 路径或 15,000 点）后等 `endOfFrame`，单次 Timer 每 50 ms 检查已调度帧及 transient callbacks，也用 Scheduler 的帧时间戳捕获两次检查间经过的帧。观察满 200 ms 静止后在帧外任务中执行。持续动画会阻塞 `Priority.idle`，故 3 s 到期直接从 Timer 执行一份快照，把干扰限制在一次采集。提交后停止轮询，isolate 复用结果。通过后只有冷解析可启用合并，已缓存和在途 Picture 沿用原结果。

## Android 120 Hz

SM-A566B、DPR 2.8125、Flutter 3.50.1 profile。每个后端使用同一 APK，轮换自动、强制关和强制开，各三次冷进程。两个 APK 以 `XVG_BENCH_JNI_DIR` 注入上一轮 ARM64 JNI，逐包核对 `libxvg.so` SHA-256（`bd035b96…837c6`）及实机渲染器日志。新阶段测量未运行 Perfetto。

## 旧版「探针后」峰值归因

1. **SVG 切换到复合路径，或位图缓存重建。未成立。** 旧场景的 192 条路径逐条交替色，Rust 只合并同画笔的相邻路径。旧基准只解析一次，始终重放同一张 Picture，未走 XVG 位图缓存。本轮强制开把四边形从 192 合到 12。Vulkan 两个动画段的峰值三轮均下降，OpenGLES 首段下降 0.27–3.14 ms，恢复段峰值增加 0.20–0.92 ms，但三轮 p95 均下降 0.52–5.98 ms，未复现持续绘制回退。结论限于该基准图。
2. **旧峰值主要来自探针工作延迟返回。未获支持。** 六个旧峰值距最后一次像素比较结束 27.50–108.64 ms。逐帧 Perfetto 对齐后，Vulkan 在 `AcquireNextSurface` 内的 `waitForBufferRelease` 等了 **7.01–11.67 ms**，OpenGLES 在 `RenderPassGLES::EncodeCommandsInReactor` 内经交换链等了 **9.30–10.16 ms**。两后端峰值帧扣除该等待后分别为 **1.78–2.00 / 2.74–3.10 ms**。同一旧 APK 关闭探针但启用同样的 trace，也复现缓冲等待及 **9.75–12.24 / 12.13–15.35 ms** 的峰值。
3. **旧对照窗口和采集条件不同。成立。** 旧关闭组未开 Perfetto，窗口沿用的是探针**开始**偏移。改为同一个探针后偏移，未追踪对照仍为 1.86–2.76 / 4.10–5.43 ms，单改窗口解释不了差距。后续对照应同时固定窗口和 Perfetto 条件，报告交换链等缓冲的耗时，并用 raster p95 检查是否持续回退。

Windows 保留跳过探针。上一轮三轮均无探针事件，web-543、web-415 与 C1 `c78eda18` 逐像素一致。[Windows 像素对照](windows_merge_diff.md)

### 单像素跳变收口

**Windows OpenGLESSDF**。最终版 DLL 启动 3 个进程，每个进程对稳定显示的 web-481 组件图层连续读回 10 次，尺寸 310×450，DPR 1，图层原点为 `(157,28)`。30 张预乘 RGBA 均与对应历史 C1 默认图层逐像素一致。目标 `(160,267)` 始终为 `[184,184,182,255]`，全图最大通道差为 0，62 级跳变 **0/30**。三轮均为 12,511 条路径，自检返回禁用且用时为 0，`xvg.pathMergeProbe` 系列事件为 0。

**手机 Impeller Vulkan**。最终版先从 web-481 的冷解析触发自检，两个进程各通过一次，最大自检差为 0。清空 Picture 缓存后重新冷录制，两个进程的路径数均由 12,511 降至 5,942。每进程连续读回 10 次组件图层，尺寸 872×1266，DPR 2.8125。20 张图的全图 SHA-256 一致，彼此最大通道差为 0，目标坐标始终为 `[0,0,0,0]`，跳变 **0/20**。相比历史 Vulkan C1，目标坐标差为 0，每张图固定有 89 个像素变化且最大通道差为 1。
