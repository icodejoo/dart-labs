# 路径合并后端自检

**定论。** Windows GLES+SDF 自动关闭合并，五图与 C1 `c78eda18` 逐像素一致。SM-A566B Vulkan 两次自检均以 0 级差通过，五图最大差 1，web-481 首次原生快照从 62.29 降至 39.04 ms（−37%）。同机强制 OpenGLES 也通过自检。Web 和 Skia 在后端预判阶段保持独立绘制。

首次记录达到 100 条路径或 15,000 个主几何点的 Picture 后，等待帧提交，再用空闲任务采两张 128×128 逻辑像素的离屏图。当前设备 DPR 下比较逐条绘制与同画笔复合路径的预乘 RGBA。最大通道差 ≤1 才开启后续冷解析的 A 档合并，结果在 UI isolate 内复用。源串和 `currentColor` 继续作为缓存键，已缓存和在途 Picture 沿用原绘制结果。

亚像素薄矩形和厚矩形分别检查最小覆盖扩边与矩形镶嵌路线，细直线检查图元快路径，凸三角与凹形检查独立／复合扫描转换，二次和三次曲线检查曲线覆盖。贴边细描边覆盖裁剪边缘，完全在画布外的细描边按 Rust 规则在两侧均独立绘制。开发版把它并入复合路径时，Vulkan 分组对照差 41 级。嵌套轮廓覆盖 even-odd、nonzero 及先填后描。此前 Chrome 内联与 `<img>` 双参照均发现解析式 AA 的有向退化，保守版只减 0.6% 路径。[跨渲染器像素裁判](windows_merge_diff.md)

Android OpenGLES 以 `ImpellerBackend=opengles` 强制，并核对引擎日志。同一 APK 的自动判定与强制关闭对照中，web-481 和 web-263 分别有 90 和 13 个像素相差 1 级，其余三图逐像素一致。Metal 本轮无实测。

1,000 图标冷滚动各三轮，漏帧为 C1 `1/1/1`、新版 `1/1/4`。UI p95 均值 3.21 → 3.42 ms，光栅 p95 / p99 为 3.92 / 5.40 → 4.46 / 6.69 ms。三轮结果不足以确认无退化。图标冷进程未触发探针，两档开关与 C1 的 473,369 字节 SSE 完全相同。

Rust 128 通过、3 忽略。Windows 1 MiB 栈审计六轮均通过，每轮覆盖开关两支。Flutter 2,101 通过、7 跳过。Dart 格式化 190 个文件、0 改动，分析只有既有 8 条弃用 info，native/web 桥接校验通过。Windows 六个对照进程均通过安静窗口检查。本轮 Android APK 的 ARM64 so 均与 `XVG_BENCH_JNI_DIR` 产物哈希一致，Vulkan APK 与 C1 的非签名条目仅 `libapp.so` 和 `libxvg.so` 不同。设备 APK、设置和 ADB 转发均验回，运行目录已清理。[逐轮数据](raster_cache_auto_merge_probe_raw.json)
