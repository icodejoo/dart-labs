# 图片坐标位图缓存真机复测

## 原型（历史数据）

默认模式仍走屏幕物理坐标的自动缓存。内部测试覆盖可选择强制关、图片坐标 A 或图片坐标 B。三种缓存方式都用点数 ≥15,000 或路径数 ≥100 的复杂度门槛。原屏幕模式另有 32 帧稳定重放和单图 12 MiB 上限；图片模式按实际视口判断预算。

- 目标尺寸为布局宽高乘 DPR 和合成变换的最大轴向缩放，各边向上取整。以现有 `PixelSnapLayer.accumulateSceneTransform` 读取物理变换和裁剪。支持的累计变换内，平移、滚动和外层透明度不改变栅格坐标。
- 整图每边 ≤4096 px 且总面积可负担时用一张纹理。更大时使用 512 px 图片坐标块、2 px 共享采样边和 64 纹素预取带。每帧至多生成一块，全局同一时刻至多一个异步请求。屏外块可供 LRU 回收，滚动回原位置可重用尚未被淘汰的块。
- 分辨率比值在闭区间 `[0.8, 1.25]` 内复用。越界且目标停稳 150 ms 后生成新网格，停稳判断忽略相对幅度 ≤0.5% 的变动。布局变化也等 150 ms，DPR 变化进入分辨率比值判断。新分辨率在屏块齐备前用旧网格预览。四倍缩回时也重采样以回收高分辨率纹理。
- 变换未知时保留已有位图。第一次遇到未知变换时，只有能按 DPR 生成的整图可以立即缓存。超大图新露出区域优先用仍驻留的旧整图预览；从未生成过预览或预览被逐出时，该区域用向量补齐。
- 静止并与物理纹素 1:1 对齐时用 `FilterQuality.none`，有缩放或亚像素位移时用 `FilterQuality.low`（线性采样）。图片模式不主动修改 Flutter 合成变换。
- A 在提交向量帧后走 `Picture.toImage`，句柄就绪后换图；B 在第一次可用合成中走 `Picture.toImageSync` 并提交延迟句柄。两者在 Flutter raster 线程生成 GPU 纹理，Dart 只录制和提交。整图、分块与换网格期间的两套纹理共用 32 MiB RGBA8 LRU。完整可见窗口无法负担且又没有仍可显示的预览时用向量。

## 真机方法

- Samsung SM-A566B，序列号 `R5CY2359S7D`，Android 17，1080 × 2340 px，DPR 2.8125，120 Hz。Flutter 3.50.1 / engine `4d35714800b9266b6693a58e1225ecd7e9e45ed7`，arm64 profile，Impeller Vulkan。使用同一 APK 内的四种开关，轮次内按固定种子打乱顺序。
- APK 内 `lib/arm64-v8a/libxvg.so` SHA-256 为 `86463a7be4004ef0c6aed40a910663eb0355bb43d718080fd441f685d2fc41bd`，与工作区 Rust release 文件逐字节一致。SVG 语料使用运行时推送，APK 内没有 `.svg` 资源。1000 个 MDI 图标沿用仓库已有的 Dart 图标语料。
- 所有向量 Picture 先预热，各次计时前卸载原场景并清空图层纹理。页面场景用默认 Android `MaterialPageRoute` push/pop，目标页用 web-543（104dp）、Aurora（76×304dp）、web-469（116dp）。弹窗是 300 ms 的 0.65×→1×/渐隐变换，画 Aurora。Hero 用 web-469 在 104×53dp 与 330×168dp 之间往返。
- 两档连续滚动都是同样 36 个刚达到复杂度门槛的语料 SVG，以 48dp 或 200dp 盒子居中适配。图标是 8 列、1000 个不同的 32dp MDI 图标。三个滚动都由列表顶部线性滚到底部，耗时 1.65 秒。
- InteractiveViewer 绘制 web-469，视口 360×300dp。程序驱动 720 ms 动画 1×→4×、停 1 秒、720 ms 缩回、再停 1 秒。独立的小色块持续请求新场景，以覆盖停稳期间的缓存生成。截图测量独立于计时，分别在 1× 稳定时和实际 4× 动画结束后停 1 秒采集视口 PNG。
- 每轮在动作窗口内用 `FrameTiming` 取 raster p50/p90/p99（nearest rank），再对各轮的统计值取中位数。掉帧数按相邻已报告帧之间缺失的 120 Hz VSYNC 槽估算；原始数据另记录 VSYNC 到 raster finish 超出 8.33 ms 的帧数。掉帧估计包含 UI、raster 排队和平台调度影响。
- 生成次数是缓存请求数。提交帧峰值用请求前最近的 UI build start 关联 `FrameTiming`，可包含该帧的向量或位图绘制。原生峰值取 VM Service Embedder trace 的 `DoMakeRasterSnapshot` 区间，反映 raster 线程在快照调用中的墙钟时间。快照若不落入 `FrameTiming` 的 raster 区间，直接帧归因记空；所以须并读两列。A 的 Future 包含 raster 排队、生成和回传，B 的同步句柄返回耗时只度量 Dart 发起请求。
- 驻留 MiB 为计时窗口内共享账本的峰值，再取三轮中位数。只计实际纹理尺寸 ×4 字节，不含 Impeller 临时渲染目标、驱动缓存和 Picture。另记录缩放端点驻留字节。
- 手机系统热状态按约 1 秒轮询。仅热状态全为 0 且结束状态为 done 的轮次进入统计。

## 原型结论

- 保留现有屏幕坐标默认路径，优先对持续移动的复杂静态插画试用图片坐标 B。在六个包含复杂插画的子场景里，B 的掉帧中位数都低于屏幕模式。Hero 从 108 到 46，缩放从 125 到 23。1000 个图标在所有模式下均生成 0 张位图。
- B 的掉帧中位数在所有复杂插画子场景都低于 A。A 在 48dp 滚动的 p99 较低（23.84 vs 27.69 ms），但掉帧更多（33 vs 20）。A 在跳转时曾同时承受向量绘制和离屏生成，p99 为 198.74 ms。B 的栅格生成仍会阻塞 raster 线程，跳转中原生生成峰值的三轮中位数为 133.07 ms。计划上线时应把超重插画的生成提前到转场前，或把生成成本纳入准入。
- 先保留 `[0.8, 1.25]`、150 ms 和 0.5% 抖动容差作为原型默认值。1×→4× 停稳后约 150 ms 启动换图，缩回后账本从 15.45 MiB 回到 3.26 MiB。此次实验验证了该组参数和边界行为，参数间的优劣仍需独立扫参。
- 图片模式在上述动画负载中占优。对 4× 停稳画质或纹理内存更敏感的场景，屏幕模式仍有价值。缩放场景屏幕模式 4× 停稳约 8.13 MiB，图片模式约 15.45 MiB。

## 最终实现

静态 SVG 只使用图片坐标位图缓存。点数 ≥ 15,000 或路径数 ≥ 100 的插画在首个可用
合成帧通过 `Picture.toImageSync` 提交纹理句柄。Dart 录制和提交句柄，Impeller 在
raster 线程生成纹理。超重插画在页面转场首次生成仍需要一个长帧，原型 B 的原生峰值
约 133 ms，同一插画单张向量帧约 115 ms。此次沿用现有公开接口。

- 首次生成和缩放停稳后，按合成矩阵的两轴物理密度和亚像素平移相位录制。绘制时逆向补偿相位，使整纹素对齐并用 `FilterQuality.none` 采样。平移和动画继续复用图片坐标纹理，纹素失配时改用 `FilterQuality.low`。每轴的分辨率比在 `[0.8, 1.25]` 内继续复用。越界后相对抖动不超过 0.5% 并持续 150 ms，才开始按新分辨率生成。布局大小变化也等待 150 ms。
- 整图覆盖 Rust 内容边界，每条边最多 2,048 纹素且总量最多 4 MiB。超过任一上限时默认用 256 纹素分块。宽度 ≤ 2,048、高度 > 2,048 且高宽比 ≥ 2 的狭长插画用 512 纹素分块，以减少合成绘制次数。分块每边保留最多 2 纹素用于线性采样，只生成与视口内可见内容相交的块。对齐时直接绘制块的纹理子矩形，线性采样时才使用采样边与内块裁剪。每帧全局最多请求一个纹理。访问过的屏外块仍由 32 MiB 共享 LRU 管理，内存压力会释放屏外块。切换分辨率前保留旧网格；当前网格缺块时，用驻留整图预览或向量覆盖缺失区域。
- 保留拟合视口裁剪、未知边界回退、合成期 `ColorFilter`、两项复杂度门槛和共享内存统计。`XvgPixelSnap.auto` 用于有遮罩或裁剪风险的视口。内部覆盖只提供强制开关。

### 1× 和 4× 停稳画质及显存

最终实现从完整物理场景裁出 1013 × 844 视口，保留实际物理像素原点。历史行来自
原型的子树截图，截图原点口径有差异。每行与同次采集中强制关的向量图比较。

| 端点 | 模式 | 最大 RGB Δ | 平均 RGB Δ | 变化像素 | Δ > 8 像素 | 停稳 MiB |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 1× | 屏幕 | 0 | 0.00000 | 0 | 0 | 2.06 |
| 1× | 原型 B | 2 | 0.00885 | 12,470 | 0 | 3.26 |
| 1× | 最终 | 44 | 0.00902 | 12,519 | 11 | 1.93 |
| 4× | 屏幕 | 191 | 0.87535 | 17,554 | 14,000 | 8.13 |
| 4× | 原型 B | 173 | 1.11086 | 38,772 | 30,558 | 15.45 |
| 4× | 最终 | 64 | 0.00148 | 2,044 | 8 | 8.37 |

上表 1× 的历史显存为缩回后的停稳读数。最终实现到达 4× 后约 150.52 ms
提交首个新分块，4× 停稳 8.37 MiB，约为屏幕坐标的 1.03 倍。
缩回停稳后为 1.93 MiB。纹理账本包含驻留的缩略预览，临时渲染目标和驱动分配
不计入该口径。

Windows 单测的 1× 夹具与向量逐 RGBA 字节一致，4× 停稳分数相位夹具也逐字节一致。
Android 的 web-469 在 1× 仍有 12,519 个变化像素，其中 12,508 个的最大通道差为 1–2，
11 个超过 8。小差值的量级符合离屏 RGBA8 合成与舍入，少量较大的差值仍在边缘。
真机 1× 逐字节一致未达到。

### 测试变更

原型行为用例继续覆盖 1:1 像素、分数平移与透明度复用、双向缩放、布局和 DPR、
不支持的变换、滚动复用及图标／预算回退。新增 `settled fractional phase matches vector pixels`
和 `visible-only tiles leave no holes during zoom and scroll`，分别直接比较像素及检查
缩放和滚动期间的覆盖。旧用例调整如下。

| 旧用例 | 处理原因 |
| --- | --- |
| `brief scale change falls back and reuses the original grid` | 删除。B 在短时缩放中直接复用旧图，已由双向缩放用例验证。 |
| `tiles evicted during scale motion can be regenerated on return` | 删除。缩放时的同步回退及对应淘汰时机已移除。新无空洞用例验证内存压力后的补齐及重建。 |
| `a settled scale replaces the original grid` | 删除。80 ms 屏幕网格等待及其逐帧断言由原型的 150 ms 双向缩放用例替代。 |
| `releases tiles when scaled beyond 12 MiB or scrolled out` | 删除。旧的 12 MiB 单图上限已移除。新预算与离场用例验证共享 LRU。 |
| `does not generate tiles during continuous translation` | 删除。首次移动帧允许缓存，连续分数平移的复用由原型用例验证。 |
| `keeps pixelSnap auto vector pixels until a grid is admitted` | 删除。自动像素对齐只受原有风险标记控制，首帧准入用例检查缓存前后的边界类型。 |
| `clipped scroll keeps nearby tiles and disposes distant rows` | 删除。毗邻行主动预取已移除，滚动用例检查已访问块的复用。 |
| `cached auto snaps filter artwork and reuses tiles during scroll` | 删除。缓存接入不触发对齐，滤镜和滚动分别由像素和复用用例验证。 |
| `cached never skips snapping and waits out fractional scroll` | 删除。分数滚动不等待相位停稳，原型的分数滚动用例验证复用。 |
| `scale 1 preserves snapped vector coverage and scale 0.5 has no tile seam` | 删除。半分辨率覆盖已移除，保留 1:1 RGBA 比较与跨块模糊覆盖。 |
| `admits a contained illustration on its 32nd stable replay` | 改为首个合成帧即准入，并检查 `pixelSnap.auto`。 |
| `memory pressure evicts adjacent tiles while keeping visible ones` | 改为先滚动生成驻留块，再验证内存压力只淘汰屏外块。 |
| `lower budget evicts offscreen first and paints missing tiles with vectors` | 改为用访问过的块验证 LRU 优先释放屏外纹理及预算不足时的向量输出。 |
| `theme, size and resolution changes replace the static grid` | 改为检查主题替换、`ColorFilter` 复用，布局和分辨率由原型用例覆盖。 |
| `source replaces tiles immediately and DPR waits for a stable grid` | 改为在 DPR 停稳前继续报告可绘制的旧纹理。 |
| `kept-alive artwork repaints when scrolled back into view`、`releases the composite when mounted artwork leaves the scene` | 改为检查离场释放合成录制、驻留图进入可淘汰状态及回场复用。 |
| `the submitted composite survives until replacement or clear` | 改为验证重复合成复用同一录制，且清理前已提交场景仍能读回。 |
| `complex SVG with unknown bounds caches the full viewport` | Rust mock 集成用例改为检查首帧单纹理及完整视口字节数。 |
| 整图、稀疏边界、溢出、滤镜及拼缝用例 | 根据 256 纹素网格和内容裁剪调整数量及取样位置，保留像素和驻留断言。 |
