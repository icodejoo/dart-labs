# Impeller Vulkan 独立路径与多轮廓路径微基准

## 结论

- **四种形状全量合并都更快，1k 至 80k 未出现反转。** 对每种形状和数量，C 的 UI 录制、净 raster p50、净 raster p90、原生快照在对应的五轮里均低于 A。1k 是最低采样点，收益从这一档已可见。80k 时，C 的净 raster p50 下降 87%–93%，原生快照下降 79%–91%。
- **矩形快速路径存在，80k 仍然能从合并中获益。** 单矩形 `drawPath` 和显式 `drawRect` 的净 raster p50 在 10k 都为 12.53 ms，在 80k 分别为 109.56、110.42 ms。80k 直接 `drawRect` 将录制从 228.61 ms 降至 76.11 ms。全量合并后，净 p50 为 14.64 ms，快照为 29.10 ms。
- **1024 是 80k 档最快的分组。** 在 D16、D128、D1024 中，1024 对四种形状的净 p50、净 p90 都是五轮逐轮最快，快照中位数也都是最低。10k 档，净 p50 最快组多为 128，凸四边形为 1024，四种形状的快照则均为 1024。1k 档组间排名随形状和指标变化，多个净值贴近 spinner 基线。
- **合并后的填充路径没有造成假设中的净增量。** 这个 SDK 的 `DisplayListBuilder::DrawPath` 对可识别的矩形直接记录 `DrawRect`。Impeller 的 `FillPathSourceGeometry::GetResultMode` 为凸轮廓返回普通模式，多轮廓 non-zero 填充进入 `ColorSourceContents::DrawGeometry` 的 stencil-then-cover。在本次输入上，合并后的整体 raster 和快照仍然下降。上一轮 web-543 的 171 → 199 ms 在这次纯引擎负载中未重现。

80k 的 A → C，中位数，单位 ms。

|---|---:|---:|---:|---:|
| 轴对齐矩形 | 228.61 → 36.55 | 109.56 → 14.64 | 110.82 → 14.61 | 140.77 → 29.10 |
| 30° 凸四边形 | 235.03 → 41.68 | 154.89 → 14.58 | 156.76 → 14.41 | 186.84 → 26.53 |
| L 形凹多边形 | 237.51 → 47.01 | 296.91 → 20.03 | 299.32 → 19.99 | 331.64 → 30.58 |
| 三次曲线水滴 | 231.79 → 52.85 | 301.48 → 26.97 | 306.01 → 26.98 | 331.88 → 38.94 |

## 方法

- Samsung SM-A566B（`R5CY2359S7D`），Android 17，arm64 profile。启动日志核验 Impeller Vulkan。沿用上一轮实测的 Flutter 3.50.1、Dart 3.14.0，engine `4d35714800b9`。仓库的 `.fvmrc` 指定 3.47.1。
- 应用直接使用 `dart:ui` 录制并向 `FlutterView` 提交场景。图案坐标和离屏快照都是 1080 × 1080 物理像素。每种图形以同一种不透明实色、默认 non-zero 填充和开启抗锯齿绘制，图形长宽约 2.4–3.0 px。四种几何分别为轴对齐矩形、旋转 30° 的凸梯形、六边 L 形和三段三次 Bézier 水滴。每个数量的中心点排成等距方格，各画法复用相同的坐标、轮廓和顺序。80k 时格距约 3.82 px，各轮廓互不重叠。
- A 每个轮廓单独录制为一个 `Path` 并调用 `drawPath`。B 只用于矩形，每个矩形单独调用 `drawRect`。C 将全部轮廓追加进同一个 `Path`。D 按网格遍历顺序每 16、128 或 1024 个连续轮廓录成一个 `Path`，尾组保留实际大小。1k 的 C 和 D1024 具有相同的轮廓分组，可用来观察重复测量的波动。
- 共 63 组，每组 5 个有效试次。每轮使用 `20261127 + 轮号` 随机打乱 63 组，先测完录制和重放，再按该轮相同顺序单独测快照。每轮重启进程并预热各类形状。主机循环采样 Android 热状态，读到大于 0 时结束进程、作废该次采集，降温至状态 0 后重试。大组预检在五轮之前单独采集。

## 计时口径

| 指标 | 每轮的测量值 |
|---|---|
| ① UI 录制 | UI isolate 上的 Stopwatch。包含创建 `PictureRecorder`、Canvas、Paint、Path、追加轮廓、调用绘制和 `endRecording`。网格坐标预先计算。 |
| ②a 稳态 raster p50 / p90 | 直接以固定 Picture 配合独立旋转圆弧持续提交帧，几何图层设置 `willChangeHint: true`。每组先测同背景的 spinner 基线。基线与重放各舍弃 8 帧、取后续 36 个已完成 raster 的帧。对 `FrameTiming.rasterDuration` 分别取 p50（中位数）和 p90（nearest rank），相减得到净值。保留带符号结果。验证采样帧的 Picture 和 Layer 缓存计数为 0。 |
| ②b 首次快照 | 每组重新录制一张 Picture，再请求一次 `Picture.toImageSync(1080, 1080)`。以 Embedder 时间线 `DoMakeRasterSnapshot` 切片计时，包含 Impeller 从 DisplayList 准备并提交离屏纹理的工作。每个请求用时间戳匹配唯一切片，用 RGBA 回读确认完成。读取像素与等待 GPU 完成的时间在切片口径之外。 |

表中各指标按组取五轮中位数。②a 是持续重放下的 raster 线程耗时，②b 是阶段独立的原生快照切片，分别受交换链和离屏目标等条件影响。两项都用 CPU 线程时间戳计量。

## 复现

在 `benchmark/bench_app` 用本轮 SDK 依次执行。脚本临时安装 APK，恢复已有 APK 和所改的设备设置，并清理设备临时文件。

```powershell
flutter --no-version-check build apk --profile --no-pub --android-skip-build-dependency-validation --target-platform android-arm64 -t lib/drawcall_micro_main.dart
python tool/run_drawcall_micro.py --apk build/app/outputs/flutter-apk/app-profile.apk --device R5CY2359S7D
python -m unittest discover -s tool -p test_drawcall_micro.py
```

## 全量结果

315 个有效试次，单位 ms。五轮视图均为 1080 × 2340 物理像素、DPR 2.8125，报告刷新率为 120 Hz，spinner 基线帧的相邻 vsync 间隔中位数为 8.319 ms。spinner 原始 raster p50 和 p90 的跨试次中位数分别为 1.598 和 2.190 ms。净 p50、净 p90 分别扣除各自分位数，因此净 p90 可以低于净 p50。

五轮的 603 次热采样均为 0。AP 31.1–42.6 °C，机身 31.2–35.8 °C，电池 28.7–31.0 °C。最初第三轮的原生采集只得到 60/63 条快照切片，整轮作废。前两轮通过完整性检查，后三轮改用重叠的 VM service 时间窗口收集原生切片，APK 和计时事件保持相同。脚本支持用 `--resume` 从已核对的轮次继续。
