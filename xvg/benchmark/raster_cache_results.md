# StaticXvg 可选分块位图缓存真机基准

## 使用和取舍

`StaticXvg.rasterCache` 和 `Xvg.rasterCache` 默认为 `null`。Rust 静态路径可用 `const XvgRasterCache()` 启用。动画与文字使用的 Dart 路径忽略该参数。默认路径沿用原绘制层级，仅启用缓存的组件参与内存压力监听。

```dart
StaticXvg(
  source,
  rasterCache: const XvgRasterCache(resolutionScale: 0.5),
)
```

- 可见范围在场景合成时按物理像素计算，取屏幕、祖先裁剪边界与适配后绘制区域的交集。512 × 512 网格用于索引，边缘纹理按插画尺寸裁窄，并预留采样边。64 物理像素邻域内的块可预取或保留。越过邻域即释放。
- `resolutionScale` 默认 1.0，范围 (0, 1]。极低倍率按每个标准内块至少一个纹素处理。0.5 的两轴采样减半，纹理字节数精确降到四分之一。双线性采样会柔化细边和局部细节。
- `XvgRasterCache.byteBudget` 是每个 UI isolate 共享的 LRU 上限，默认 32 MiB。作为上界，两幅各覆盖 1080 × 2340 长屏的插画，在每屏取 3 × 5 个完整的带采样边块时共约 30.5 MiB。实际边缘纹理裁窄后通常更小。内存压力先清理屏外块，预算不足的区域直接用向量绘制。只读诊断为 `bytesUsed`、`tileCount` 和 `disposedTileCount`。
- 现有像素对齐层继续决定实际几何。全分辨率内块在物理网格上按 1:1 绘制。需要的块未就绪时由同一 `Picture` 填补。全局每帧最多提交一个块，首帧先提交向量。`colorFilter` 在向量和位图合成后应用，纹理可继续复用。

## 设备和测量

SM-A566B（Android 17），1080 × 2340，DPR 2.8125，120 Hz，Flutter 3.50.1 / engine `4d35714800b9266b6693a58e1225ecd7e9e45ed7`，arm64 profile。每轮 force-stop 后冷启动，日志核对 Impeller Vulkan。各组交错运行三次，33 轮开始时设备热状态均为 0。表中为逐轮中位数，方括号给出三轮范围。

页面持续显示同一个 spinner，插画宽 375 逻辑像素。两个样本分别为 233 KB 插画和[手写滤镜样本](bench_app/assets/raster_cache_aurora.svg)。合成样本使用多层高斯模糊、组透明度和渐变。两者都通过基准脚本运行时传入，向量和缓存组共用相同裁剪视口、画面尺寸及 `RustXvgPictureCache.getOrRenderAsync` 冷解析入口。

请求发生在 spinner 预热后，包含解析和录制耗时。首次完整出图以首帧向量内容的 raster finish 计，分块齐备以可见块第一次全部进入同一帧的 raster finish 计。最长准备帧覆盖请求至齐备，分别统计 raster duration 和 totalSpan。稳态窗口在齐备后再等 480 ms，持续 1.9 秒。帧完成率以窗口内首尾的 raster finish 计算。滚动从稳定的顶部开始，在 5 秒内匀速滚到底，按 totalSpan >16.6 ms 计数。

## 像素验证

Windows Flutter 3.50.1 测试引擎加载当前 Rust DLL。全分辨率和向量根场景均保留裁剪、半透明重叠及四分之一像素平移下的 `PixelSnapBoundary`。以四邻域大于 8 色阶的局部变化标记边缘。非边缘只允许一色阶的预乘合成舍入，边缘最多 24 色阶，且影响面积低于 0.5%。实测 921,600 像素中 1,899 个边缘像素超过一色阶（0.206%），最大差 20，非边缘超过一色阶的像素为 0。预算只够一个块时，混合画面也满足该阈值。高斯模糊跨缝与半分辨率渐变跨缝采样均在一色阶内。半分辨率的纹理字节数在测试和真机中都为全分辨率的四分之一。

全量测试 2,025 项通过，7 项现有可选用例跳过。缓存专项 11 项通过，测试进程模块列表确认加载本地目标目录的 Rust DLL。Dart 格式和分析、native/web 桥接一致性及预编译清单检查均通过。

## 复现

屏幕坐标、半分辨率和异步快照数据需要历史版本复现。当前版本的真机入口与参数见[图片坐标基准](raster_cache_image_space.md#最终实现)。

按[原生库复现参数](async_threshold_results.md#复现)编译 arm64。构建时暂时将 `android/build.gradle` 的 JNI 来源指向该库所在的 `arm64-v8a` 目录，构建后恢复原配置。用 Flutter 3.50.1 从 `benchmark/bench_app` 运行。

```powershell
flutter build apk --profile --no-pub --android-skip-build-dependency-validation `
  --target-platform android-arm64 --target lib/raster_cache_bench.dart
adb -s R5CY2359S7D install -r build/app/outputs/flutter-apk/app-profile.apk
./tool/run_raster_cache.ps1 -Cases @('vector:still','full:still','half:still','async:still')
./tool/run_raster_cache.ps1 -InputSvg $LocalSvg -AspectRatio (375.0 / 2114) `
  -Cases @('vector:still','full:still','half:still','async:still','vector:scroll','full:scroll','half:scroll')
```

千图标组使用默认入口，构建参数为 `--dart-define=LIB=xvg --dart-define=ITEMS=1000 --dart-define=CYCLES=6 --dart-define=AUTOEXIT=1`。两类 APK 内 `lib/arm64-v8a/libxvg.so` 逐字节匹配本地 Rust 产物，SHA-256 均为 `98a378d76d61689b71d89c577b622c5f9bee5e45feb656ec21f92577d9fd1495`。

## 局限

以上数据覆盖单一设备、单一图形后端和两个样本。纹理字节数按 RGBA8 估算，驱动分配、滤镜临时附件、引擎引用及回收时机另计。圆角、路径裁剪取外接矩形作为候选范围。未知图层或非轴对齐变换下使用向量。未启用像素对齐时，连续亚像素移动期间使用向量，稳定约 80 ms 后再补块。两组都保留原有的首次向量渲染成本。

## 终审返工复测

### 方法

- SM-A566B（Android 17），1080 × 2340，DPR 2.8125，120 Hz，Flutter 3.50.1 / engine `4d35714800b9266b6693a58e1225ecd7e9e45ed7`，arm64 profile。沿用上一轮的 spinner、375 逻辑像素宽度与顶部停稳后的 5 秒线性滚动。合成样本四组轮换起点，233 KB 组随后执行。每组 force-stop 后冷启动三次，15 轮起跑热状态均为 0，日志均确认 Impeller Vulkan。
- `-UnclippedAurora` 从原手写样本生成运行时副本，仅移除 SVG 的 `clipPath` 定义和 `clip-path` 引用。四组用同一副本，原生 Picture 的 `hasPixelSnapRisk` 均为 `false`。保留滚动视口的裁剪。233 KB 组通过 `-InputSvg` 注入，沿用宽高比 `375 / 2114`，`hasPixelSnapRisk` 为 `true`。
- 合成样本从 0 滚到 1,878.75 物理像素，标称速度 375.75 物理像素/秒，在 120 Hz 下每次刷新前进约 3.131 物理像素。逐帧用 `ScrollController.offset × DPR` 记录对齐前的位置。四组共 3,949 个位移非零的完成帧，位置与步长均带小数（离整数至少 `1e-7` 物理像素）。另有 8 帧在起点等待首个非零位移。
- 以滚动窗口内的 vsync 选帧。用引擎的构建时间戳与帧后回调关联，共 15 轮的滚动完成帧均匹配。逐帧读 `debugXvgRasterTilesReady`，统计可见块全部齐备的完成帧占比。帧速率为首末 raster finish 之间的完成速率，长帧采用 `totalSpan > 16.6 ms`，峰值使用 `XvgRasterCache.bytesUsed` 的 RGBA8 估算。
- 使用 `prebuilt/` 原生库，APK 内三个 ABI 的 `libxvg.so` 逐个与预编译文件核对一致。设备加载的 `arm64-v8a/libxvg.so` SHA-256 为 `40a18d0c1dfe01b9a62a2df13733e351dfc1867bdf78f9a8e952990d3d314f26`。上一轮使用不同 SHA-256 的本地 Rust 产物，跨轮仅对照实测指标。

### 结论

- 无裁剪合成样本在连续亚像素滚动中，`auto` 的两种分辨率每个完成帧都具备全部可见分块，raster p95 从 167.82 ms 降至 3.15 ms（1.0）和 2.81 ms（0.5）。半分辨率的峰值纹理为全分辨率的四分之一。
- `never` 三轮都保留顶部预热的 11,071,616 B 纹理，滚动期间驻留字节恒定，215 个完成帧的 raster 均超过 16.6 ms。小数偏移持续改变网格相位，缓存回落到向量。滚停后首个可见块全部齐备的 raster finish 出现在 653.83–662.34 ms，包含代码设定的 80 ms 停稳等待、分块生成和帧完成时间。
- `auto` 的长帧合计为 60 帧，全部可见块齐备，单帧 raster 均低于 16.6 ms。长帧的 build finish 到 raster start 间隔中位数为 32.54 ms（1.0）与 23.63 ms（0.5），并且每个长帧前后两个完成帧内都有纹理驻留字节增加。时序与滚动中补充或预取分块一致，逐帧数据可排除可见分块未齐备。
- 233 KB 的三轮长帧均为 0，峰值纹理均为 13,284,224 B，两项与上一轮一致。
