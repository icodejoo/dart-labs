# 磁盘位图快照的真机冷启动收益

固定首屏的重插画值得按资源、按尺寸启用 PNG 快照。233 KB 插画的首帧从 **41.74 ms 降到 25.19 ms**，节省 **16.55 ms**。公开合成插画从 **133.72 ms 降到 46.55 ms**，节省 **87.17 ms**。两份视口快照各占 **9.42 MiB** RGBA8，手机 `toByteData(png)` 分别耗时 **253.09 ms** 和 **948.67 ms**。

## 首次生成与透明度

每种大小独立生成五次。写入列含 `flush`，文件大小与离线转码使用首轮生成的 PNG。非不透明像素包括完全透明与半透明。

| 样本 | 物理像素 | `toImage` ms | PNG 回读与编码 ms | 写入 ms | 非不透明像素数 |
|---|---:|---:|---:|---:|---:|
| 233 KB · 视口 | 1055×2340 | 26.73 | 253.09 | 4.10 | 0（半透明 0） |
| 233 KB · 整图 | 1055×5946 | 43.29 | 512.52 | 5.83 | 813,405（半透明 1,055） |
| 合成图 · 视口 | 1055×2340 | 141.11 | 948.67 | 13.86 | 0（半透明 0） |
| 合成图 · 整图 | 1055×4219 | 256.61 | 1804.96 | 16.16 | 0（半透明 0） |
| 48 px 图标 | 135×135 | 2.18 | 4.96 | 3.35 | 15,306（半透明 538） |

233 KB 的视口为全不透明，整图含透明像素。JPEG 按测试白底合成，带透明的样本换背景时需要使用保留 alpha 的格式。对 233 KB 样本，Pillow 校验两份 WebP 无损都逐像素保留各自 PNG 的 RGBA。整图 PNG 裁到顶部后，在 2,468,700 个像素中有 513 个与单独生成的视口 PNG 最大通道差超过 1 个色阶，其中 11 个超过 8 个色阶。

## 取舍

- **优先固定视口 PNG。** 233 KB 视口快照占磁盘 455.8 KiB，首帧快约 16.6 ms，稳态 raster p50 从 4.66 ms 降到 1.77 ms。合成视口的 PNG 占磁盘 2.05 MiB，首帧快约 87.2 ms，稳态 raster p50 从 24.34 ms 降到 1.92 ms。设备端生成可用 Flutter 的 `Picture.toImage`、`toByteData(png)` 和 `dart:io`，无需新增 Flutter 依赖。首次生成的耗时适合留在显示关键路径之外。
- **整图和紧凑格式分情况。** 233 KB 整图 PNG 的首帧只快 1.97 ms，采样范围有重合，单份位图要 23.93 MiB。合成整图 PNG 快 56.51 ms，单份位图要 16.98 MiB，PNG 回读与编码约 1.80 s。233 KB 视口 WebP q90 占 110.2 KiB，首帧比 PNG 慢 9.78 ms。各格式的解码后像素预算相同。客户端生成 WebP、JPEG 或 AVIF 需要额外编码能力，这次用已有 Pillow 在 PC 上离线完成。
- **48 px 图标继续走向量。** 向量首帧 9.23 ms，PNG 和两种 WebP 的中位数为 7.43–8.13 ms，五轮范围有明显重合。JPEG 和 AVIF 分别为 10.94 和 106.69 ms。单份图标快照还要 72,900 B RGBA8，测得的小差别不足以支持默认开启。

## 方法

- SM-A566B，Android 17，Flutter 3.50.1，engine `4d35714800b9266b6693a58e1225ecd7e9e45ed7`，arm64 profile。每轮核对 Impeller Vulkan 日志。视口 1080×2340，DPR 2.8125，刷新率 120 Hz。
- 233 KB 插画与合成插画都按 375 逻辑像素宽度绘制，保持原比例。视口快照记录可见顶部。整图快照保持相同显示比例并保留画面下方像素，首帧依旧只看顶部。图标取 `mdiIcons1000.first`，48 逻辑像素。合成插画使用原有的公开样本。该样本开工前已在工作区，复现时需一起带上。样本 SHA-256 为 `1d43e5ea0b4777bf2ed33f27c76ed725381780ca95cb0bf913ac5395b8911d29`。[合成样本](bench_app/assets/raster_cache_aurora.svg)
- 每个模式先 `am force-stop` 再启动应用。各格式交错并逐轮改变起点。两条路径在同一白底 spinner 场景运行，预先初始化 Flutter 和 Rust，首个 Flutter 帧后等 450 ms 再发请求。向量在请求后挂载 `StaticXvg`，默认 16,384 UTF-16 码元阈值将 233 KB 样本交给 FRB worker，合成图和单图标走默认小源路径。SVG 原样读入，置于计时前以对齐既有基准。位图进程只在请求后从私有目录读取位图。
- 向量和位图共用物理像素对齐的画框和重绘边界。向量用显式像素对齐的尺寸、位置和 `BoxFit.fill`，并关闭内部自动对齐，位图用 `RawImage`。首帧以真实内容进入 paint 的单调时戳匹配引擎 `FrameTiming` 的 build 区间，计至同一帧 `rasterFinish`。逐帧 raster 是 `rasterFinish - rasterStart`，稳态从首次 raster 完成后 300 ms 起取样，截止于请求后 1.15 s。
- 读盘用 `File.readAsBytes`，解码列计 `instantiateImageCodec` 加 `getNextFrame` 的墙钟时间。该时段含 Flutter/Impeller 在返回图像前的纹理上传工作，首帧指标涵盖整条路径。独立写入轮次记录 `Picture.toImage`、`toByteData(format: png)`（GPU 回读与编码）和私有目录 `writeAsBytes(flush: true)`。以未经重压缩的手机 PNG 作为 PC 编码输入。
- PNG 保持原样。Pillow 12.3.0 生成 WebP 无损（保留 RGBA）、WebP q90（alpha 无损）、JPEG q90（白底合成、4:2:0）、AVIF q90（4:2:0，保留 alpha）。`cwebp` 和 `avifenc` 未装在本机 PATH，Pillow 已提供相应编码器。AVIF 每种尺寸先在目标手机验证，再进入正式矩阵。

## 复现

在 `benchmark/bench_app` 用 Flutter 3.50.1 串行构建和安装。Android Gradle 配置直接引用预编译目录。APK 内 `lib/arm64-v8a/libxvg.so` 与 `prebuilt/android/jniLibs/arm64-v8a/libxvg.so` 的 SHA-256 都是 `40a18d0c1dfe01b9a62a2df13733e351dfc1867bdf78f9a8e952990d3d314f26`。

```powershell
$ndk = "$env:ANDROID_HOME/ndk/28.2.13676358/toolchains/llvm/prebuilt/windows-x86_64/bin"
$env:CC_aarch64_linux_android = "$ndk/aarch64-linux-android21-clang.cmd"
$env:AR_aarch64_linux_android = "$ndk/llvm-ar.exe"
flutter build apk --profile --no-pub --android-skip-build-dependency-validation `
  --target-platform android-arm64 --target lib/snapshot_decode_bench.dart
adb -s R5CY2359S7D install -r build/app/outputs/flutter-apk/app-profile.apk
python tool/run_snapshot_decode.py --samples aurora icon --repetitions 5 `
  --output .dart_tool/snapshot_decode_runs/public.json
```

自带外部插画时，在命令中增加 `--samples external aurora icon --external-svg $LocalSvg --external-size $Width $Height`。Python 需要本机已装的 Pillow。APK 和 bench_app 无新增依赖。脚本仅把外部输入通过 adb 传到应用私有目录，在主机的仓库外临时目录编码，运行结束清理两端图像。合成整图取修复 ADB 回传截断后的完整复跑结果。逐帧记录包含数值、模式和进程标识，本次位于 `bench_app/.dart_tool/snapshot_decode_runs/matrix.json`。

## 局限

- 冷启动指进程和进程内 Picture、图片缓存冷态。ADB 写入后读盘可能命中 Android 页缓存，读盘列反映 app 可见文件访问延时。旋转格式顺序只能缓和调度和温度漂移。
- 起点在首屏 spinner 已启动、Flutter 与 Rust 已初始化之后。历史约 74 ms 来自 [此前的共享裁剪外提试验](raster_233kb_results.md#5-首次成本与内存)，该轮 Rust 产物、向量绘制配置和启动探针与本轮有差异。收益用本轮同组向量冷启动计算。
- `width × height × 4` 是解码后单份 RGBA8 预算。向量的 `Picture.approximateBytesUsed` 是引擎估算。二者都无法直接代表进程总内存，也未测编码、解码暂存和 GPU 驱动的峰值分配。首帧终点是引擎报告的 raster 完成，未测物理屏幕呈现。
- 只覆盖一台真机、固定 DPR、固定白底和这三种内容。视口快照仅覆盖首屏。继续滚动、换尺寸或 DPR 需要重建快照、额外分块或使用向量回退。
