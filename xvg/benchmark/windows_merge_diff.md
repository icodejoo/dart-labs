# 平台无关的路径合并与浏览器像素裁判

**推荐 G。** 保留薄矩形、细描边、完全在视口外的描边、曲线及填描混合路径。长边按 512 px 换算，轴对齐矩形短边达到 2 px 才允许合并，描边宽度不超过 1 px 时独立绘制。G 从 C1 的 642,348 条减至 **638,340 条**，比严格版 S 多合并 3,993 条。Windows SDF 三轮与 C1 像素一致。Skia 和 Vulkan 的剩余差只在 web-481 的边缘，未见对 Chrome 的系统性退化。

**GLES 低值定位到离屏纹理生成。** 纯 `dart:ui` 用完整 B 和 C1 画稿均复现 `(160,134)` 原始纹素下降 62 级，最近邻贴回 `(160,267)` 原样保留。消融将差异缩到未合并的黑色填充边附近，其数值对应一个 4× MSAA 样本的贡献。历史两组细描边均离该点几十像素，单独重放在目标点全透明。完整画稿中哪些绘制状态触发额外覆盖还有待验证。[GLES 低值机制](#gles-低值机制)

## 判定与收窄

1. **假设 B 的差全是无方向的抗锯齿噪声。否定。** B 仅保留所有轴对齐矩形和完全在固有视口外的描边。Skia 的 web-023 两尺寸和 web-263 大尺寸，在内联和 `<img>` 参照下都更远。内联参照下，变化区域的每通道平均绝对误差增量 95% 区间分别为 +0.225～+0.389、+0.430～+0.527 和 +0.616～+0.795。Windows 的 web-481 在 B 的 2/3 轮中有一个 62 级变化像素，两种参照都判为变远。H 在 Windows 的 web-543 上 MAE 从 8.916 升至 17.753，35,738/36,007 个变化像素变远。H 的 web-415 在 Windows 上略更接近 Chrome，Skia 两尺寸均退化。
2. **假设通过路径形态可以去掉退化。成立。** 逐条匹配 C1 与 B 的点、动词及画笔。web-263 大尺寸的 1,313 个变化像素都落在多轮廓填描路径的外扩包围盒内。web-023 参与合并的成员为 2,048 条曲线填充和 224 条带描边的曲线。web-481 的 Windows 跳点在约 0.32 px 的描边附近。F 保留全部矩形、曲线、填描混合路径和细描边，延续 B 的视口外描边规则。web-263 和 web-023 在 Skia 两尺寸归零，Windows 跳点在三轮均消失。
3. **假设处于普通覆盖范围的厚矩形可以放开。五图支持。** G 放开参照尺度下短边至少 2 px 的矩形，与 F 在全部四组采集逐像素一致，多合并 173 条。web-415 原先参加合并的 4,150 个矩形成员短边仅为 0.0296～0.0494 个参考像素，因此两版均保留 4,945 条路径。G 的 web-481 在 Skia 小／大尺寸差 37／131 像素，最大差 2／7，两种 Chrome 参照的误差增量区间均跨零。Vulkan 两轮各差 47 个像素、最大 1 级，36 个变近、11 个变远。
4. **假设回归与递归的栈帧有关。成立。** Win64 debug 反汇编的 `.seh_stackalloc` 显示父提交 `6e9bee60` 为 7,720 B，H 为 7,776 B（空实现）／7,744 B（合并）。另有保存寄存器 32／40 B，空实现每层实际多 64 B。用 `#[inline(never)]` 将路径转换与效果的临时值移到叶子函数，G 的两个递归帧分别降到 2,960／2,944 B，保留静态分派。既有 1 MiB 审计失败数为父提交 0/6、H 3/6，G 重跑 0/6。

## 验证与上轮记录

`cargo test` 126 通过、3 忽略。`dart format lib test` 格式化检查 189 个文件。`dart analyze lib test` 仅既有 8 条 `material.dart` 弃用 info。以最终 release DLL 位于 PATH 首位运行全量 `flutter test --concurrency=1`，2,103 通过、7 跳过，0 失败。 Windows 本轮 9 个进程均检查 640×360、右下角压底和无前台激活，未出现焦点违规。B 保留三轮逐样本的像素哈希和原生快照事件，其窗口明细汇总被后续批次覆盖。手机两批均验回原 APK SHA-256、常亮、刷新率和 ADB 转发，应用目录和临时数据已清除。

## 单像素跳变根因

下文保留组件层的历史记录。新的纹理原件回读、C1 对照和填充消融见 [GLES 低值机制](#gles-低值机制)。

**组件层根因。** Windows OpenGLESSDF 的 B 档在生成并采用新的图片坐标位图缓存时，有一轮把合并描边附近 `(160,267)` 的覆盖带入了低值状态。只要保留这张纹理，重复读回就保持 `[122,122,120,255]`。同一 Picture 的矢量直绘、等相位离屏回放以及换掉该纹理后的读回都回到 `[184,184,182,255]`。定位范围是 `XvgRasterCache` 的 `toImageSync` 缓存生成到首次贴图之间。现有测试钩子能看到纹理尺寸、请求和使用状态，无法直接读取生产出的纹素或引擎内部的覆盖中间值，因此无法进一步确认 GLES 内部选择低值的条件。

### 第 1 步 · 重复历史低值

**假设。** 归档 B DLL 在相同环境中仍能生成同一张低值图。**成立，触发取决于缓存实例。** Flutter 3.50.1 profile（引擎 `4d35714800`），Git `9cc6a831` 的 Dart 入口配归档 B DLL，web-481 为 5,954 条路径。每进程分别采自动缓存、禁用缓存、恢复缓存预算后的强制缓存，以及预热重挂载自动缓存各 30 次。三轮均为 310×450、DPR 1、组件原点 `(157,28)`，同一输入和同一 DLL。

| 采集条件 | 进程 1 | 进程 2 | 进程 3 | 低值读回合计 |
| --- | ---: | ---: | ---: | ---: |
| 自动缓存，冷挂载 | 0/30 | 0/30 | 0/30 | 0/90 |
| 强制禁用，矢量直绘 | 0/30 | 0/30 | 0/30 | 0/90 |
| 强制启用，从零恢复预算 | 0/30 | 0/30 | 30/30 | 30/90 |
| 自动缓存，暖重挂载 | 0/30 | 0/30 | 0/30 | 0/90 |

第三轮第一次低值为该条件第 1 次、全程第 62 次读回、引擎帧 67、距首张图稿提交 5.553 s。该纹理一直复用到条件第 30 次、帧 97、6.136 s，期间没有新请求。命中率为 1/3 个进程中的缓存重建，条件内为 30/90 次读回，这 30 次共享同一张纹理。之前的零预算第 61 次采集为高值。第三轮恢复预算后请求一张 310×184 RGBA8 纹理（228,160 B），同一挂载内从 0 块变为 1 块。原生 `SnapshotDisplayList (impeller)` 在首个低值读回发起前 0.533 ms 开始，历时 47.474 ms，随后完成图层快照。异常整图的 RGBA SHA-256 与历史 B 的两张异常图完全一致（`35948a0456d891f5ece2f9279584d65f132ded79ece7b7aca0c4b1783d8dd8b2`）。相对高值图（`8f749fd8fd0e18af9324f105a143de2debedea5db18cbafabb788cdd3de21fd7`）只变了目标 1 px，RGB 各降 62、alpha 不变。

### 第 2 步 · 对照与收窄

1. **假设 (a) 是跳变随矢量直绘切到缓存发生。成立。** 自动档各进程首采前已返回一张 310×184 图片句柄，均未跳。强制禁用的 90 次与零预算的 3 次均为零块、高值。恢复预算后，三个进程各生成一张相同尺寸纹理，其中第三轮出现低值并稳定复用。放大到 1.40 倍时，早期复用 341×202 纹理，静置后请求 434×257，目标值随缩放及重建改变，回到 1.00 倍重建后恢复高值。代码的复用带是 0.8–1.25，停稳时间 150 ms。基准从 1.00 切到 1.10 时插入了变换层并重新挂载，因此这一步无法单独验证带内复用。固定尺度的原位对照不受该布局变化影响。
2. **假设 (b) 是同一 Picture 逐次回放会随机跳变。对照不支持。** 每个进程用固定 Picture 按两种固定相位各 `toImage(310,450)` 50 次。无对齐修正的 150 次全部为 `[180,180,176,255]`，应用实测 PixelSnap 矩阵的 150 次全部为 `[184,184,182,255]`，且与高值组件图逐字节一致。两档各自跨三个进程只有一个整图哈希。该实验排除了对应离屏条件下的逐次波动，缓存生产时的 GLES 内部状态仍在定位范围内。
3. **假设 (c) 是窗口或 PixelSnap 相位变了，造成历史低值。原位对照否定。** 低值前后，DPR、窗口、组件原点、PixelSnap 矩阵完全相同。矩阵为 `sx=1, sy=1.0018414254, tx=0, ty=−0.4143207260`。裸回放改为对齐后，点值从 `[180,180,176,255]` 变成 `[184,184,182,255]`。关闭 PixelSnap 并平移 `−0.25 px` 时，点值可到 `[124,124,123,255]`，整图和历史低值不同。启用 PixelSnap 后同样的 `−0.25 px` 平移恢复高值，整图也恢复。相位会影响细线覆盖，原位跳变前后的有效相位相同。
4. **假设 (d) 是第一帧的管线着色器与预热后不同，导致低值。对照不支持首帧解释。** 冷挂载 0/90，预热后重挂载 0/90，唯一低值组在首图 5.553 s 后才开始，之前同进程已读 61 张图。三进程 VM timeline 能统计 `PendingProgram::Compile`，次数为 122、118、114。逐事件筛选没有保存该事件的时间戳和 pipeline 标识，无法用这份记录排除缓存生成时某个变体参与。

### 第 3 步 · 合并与发布范围

**假设。** 异常需要历史合并表示和缓存路径同时参与。**现有对照支持。** 旧 B 的低值只在有缓存的组件层出现。历史 C1 的三进程 30 次为高值，覆盖稳定缓存、禁用和重挂载。用实测相位复算归档路径，目标中心落在 9 条参与合并的细描边扩展包围盒内，宽度约 0.321 px。旧 B 会把相离的相同画笔路径编入同一复合轮廓，改变 Impeller `StrokePathGeometry` 收到的描边轮廓组合。F/G 保留细描边后三轮各为高值。归档的单组几何重放没有复现这个 62 级点，因此仍无法锁定某一条成员路径或着色器。

**发布配置核对。** `lib/src/path_merge_probe.dart` 的 `debugShouldProbePathMerge` 对 Windows 返回 false，`_pathMergePassed` 初始为 false，发布没有测试覆盖，Rust 收到 `allow_path_merge=false`。此前发布入口在 Windows 的 3×10 组件读回均为高值，保留 12,511 条路径，自检计时和事件均为 0。本轮三个 Windows 进程全部用于历史 B 条件，HEAD 的 x64 prebuilt 哈希单独校验。
