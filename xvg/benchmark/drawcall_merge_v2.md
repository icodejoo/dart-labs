# 静态 SVG 路径合并 v2

## web-543 快照回退的假设

旧隔离测试的 20 个正式试次（C0/C1 × A0/A1 × 5）各只请求一张 **872 × 873** 纹理。总大小约 2.90 MiB，低于整图 4 MiB 和 2048 像素单边阈值，256/512 纹素分块都未启用。关闭 A 时，C0 → C1 的快照仍从 **179.97 → 213.98 ms**。因此跨块重复回放无法解释这次回退。合并改变了同一张纹理里提交给 Impeller 的路径形态，细分、覆盖率或填充策略的具体贡献没有单独测量。 [原 2×2 隔离结果](drawcall_merge_isolated.md) · [微基准](drawcall_micro.md)

## 结果

- **默认 256/128，web-543 首显优先时用 128/128。** 256/128 在 714 张图中少 74,060 条路径（−11.53%），较 128/128 再少 9,543 条，web-481 的录制和首次快照从 C0 的 56.12 / 59.11 ms 降到 19.77 / 31.30 ms。512/128 再少 6,274 条，未入选手机实测。相同跨度下，组上限提高到 1024 的路径数、命令数和 SSE 字节数逐图一致，保留较小的 128。
- **web-543 原尺寸仍有整图快照回退。** C0 / C v1 / v2 128/128 / v2 256/128 分别为 170.85 / 205.42 / 193.47 / 213.38 ms。128/128 的完整显示比 256/128 提前 52.72 ms。真实 2× 分块时四版各生成 30 块，原生活跃总量依次为 150.15 / 189.38 / 176.06 / 179.34 ms。v2 两档均缩短 C v1 的逐块总成本，仍高于 C0。
- **收益按图稿变化。** 256/128 在 web-481、web-415、web-263 的录制、快照和完整显示均快于 C v1。web-544 的完整显示比 C0 晚 114.62 ms。1000 图标滚动漏节拍中位数从 C0/C v1 的 4 增至 v2 两档的 7/8。
- **两档 v2 都有像素差。** 分别与 C0 比较，C v1 为 65/65 对一致，v2 两档均为 50/65。web-481 最大差 23 通道级，web-002 和 web-263 最大差 1。web-543 原尺寸和 2× 五轮均逐像素一致。

## 实现口径

- 默认档位为 **256 / 128**。把固有长边归一化为 1024 纹素，合并后两轴含描边与间隙的跨度都不得超过 256 纹素，每批最多 128 条。只合并同一个 usvg 组内连续绘制且回放画笔逐项相等的路径。组、裁剪状态、层混合、拆出的 marker 绘制和图像保留各自的顺序。带遮罩或模糊的路径保持独立。
- 实色填充与非重叠半透明填充可参与。渐变比较色标、透明度、坐标系与矩阵，图案比较解析后的贴片与矩阵。普通描边计入端点、连接、斜接限制和仿射外扩，预展开的描边使用轮廓点。半透明描边和透明度未知的图案描边保持独立。
- 使用全部端点与二次、三次贝塞尔控制点构建保守凸包。组内包围盒按固定网格索引，先排除不相交的边界，再对候选运行 GJK。每形外扩半个间隙，两形共留固有长边的 2/512。正方形的支撑点可直接加进 GJK 计算，且各方向至少覆盖所需半径。凸包相切或 GJK 未收敛时保留独立绘制。
- 只移植凸包和 GJK，输入取 XVG 的 f32 路径点，运算用 f64。源文件保留仓库、版本、文件路径与版权，版权为 2024-present noahbald，MIT。 [OXVG v0.0.10 源码](https://github.com/noahbald/oxvg/blob/v0.0.10/crates/oxvg_path/src/gjk_intersection.rs) · [许可证](https://github.com/noahbald/oxvg/blob/v0.0.10/LICENSE)
- Dart 恢复一次性 Picture 录制和原本的冷挂载调度。默认固有尺寸修复保留，根元素同时缺少 width、height 和 viewBox 时使用 300 × 150。

## 测量与复现

- C0 与 C v1 使用指定的旧 so。两个 C v2 so 由同一源码分别以 128/128 和 256/128 重编。四份 profile APK 依次通过 `XVG_BENCH_JNI_DIR` 构建。解包后除签名和 arm64 `libxvg.so` 外，112 个条目内容一致。Flutter 3.50.1，Dart 3.14.0，engine `4d35714800b9`。
- 固定 310×450 逻辑像素图稿框，视图为 1080×2340 物理像素，DPR 2.8125。每轮以 `20261127 + 轮号` 分别随机化版本和样本顺序，同轮各版共用样本顺序。除指定样本外，加入路径减少最多的三张未覆盖语料 web-481、web-415、web-263，以及同一 web-543 的 2× 分块试次。
- 冷分段在 FRB worker 路径测 ②a SSE 解码，并从 Canvas 创建钩子计到 Picture 录制完成测 ②b。另一趟冷页面试次持续转圈，在读完数据后交给实际 `StaticXvg`。完整显示从交付到首个实际图稿帧的 `rasterFinish`，漏节拍由该阶段相邻 `vsyncStart` 估算。
- 逐块把纹理提交与原生 `DoMakeRasterSnapshot` 配对，稳态从首图和最后一次原生快照都完成后再等 50 ms 开始。普通尺寸在首图后观察 450 ms，2× 保留 6 秒让分块队列排完。最初 1.8 秒的预检在截止时还有纹理请求未执行，整组弃用。
- 每次冷页面计时后，独立重绘并采集图稿区域的 872×1266 预乘 RGBA。单个图标与插画使用同样的捕获口径。1000 图标滚动从冷 Picture 缓存开始，以 1650 ms 的线性滚动遍历网格。只给性能试次与像素读回使用的公开语料和 233KB 插画在 APK 安装后经 adb 推送。

在 `benchmark/bench_app` 下为每版依次设置 `XVG_BENCH_JNI_DIR`，指向含 `arm64-v8a/libxvg.so` 的目录。

```powershell
flutter --no-version-check build apk --profile --no-pub --android-skip-build-dependency-validation --target-platform android-arm64 -t lib/ui_thread_decode_record_main.dart
python tool/run_drawcall_merge_v2.py --illustration $Illustration --extra web-481 web-415 web-263 --build C0 $C0Apk $C0So --build C1 $C1Apk $C1So --build C2-128x128 $C2SmallApk $C2SmallSo --build C2-256x128 $C2Apk $C2So
```

Rust Android 构建使用 NDK 28.2、aarch64 API 21 linker 和 16 KiB 对齐。基准构建可用 `XVG_MERGE_SPAN`、`XVG_MERGE_MAX_PATHS` 选择档位。Windows 扫参 DLL 构建时设 `XVG_MERGE_SWEEP=1`，执行时用这两个变量切档，每次同样要提供仅本机可读的语料计划。

```powershell
dart tool/drawcall_corpus.dart $Dll $CorpusPlan $ResultJsonl
```

## 像素、热状态与构建核验

- C0/C1 有 65 / 65 对逐像素一致。
