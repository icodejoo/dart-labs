# 静态 SVG 合并绘制与分帧录制的真机 2×2 对照

## 结论

- **C 单独开启时，web-543 的录制更快、首次快照更慢，完整显示仍提前。** C0A0 → C1A0 的 ②b 为 246.58 → 182.36 ms（−26%），③ 为 179.97 → 213.98 ms（+19%），完整显示为 1185.51 → 1142.12 ms。三项在五个配对轮次里各自方向一致。A 开启时，web-543 的 C 快照回归同样出现，168.10 → 202.05 ms，五轮都变慢。因此上一轮 web-543 的 171 → 199 ms 在关闭 A 后仍能重现方向。
- **C 的首次快照表现随样本而变。** A0 下，web-541 减少 6,393 条路径，录制 66.30 → 46.65 ms，③ 51.85 → 38.18 ms，完整显示 325.18 → 276.67 ms，三项均是五轮下降。web-545 的录制 60.59 → 37.71 ms，完整显示 309.36 → 270.10 ms，两项五轮均下降，③ 大致持平。web-544 路径只减约 1%，两档 A 下的录制及快照中位数变幅均在 5% 内。web-150 和 web-002 的路径数与 SSE 字节数相同，作为无合并对照。
- **A 单独开启时，两张最重图的录制峰值约降九成，代价是更晚显示和更多漏节拍。** 固定 C0，web-543 的单帧峰值 246.58 → 23.09 ms，完整显示 1185.51 → 1613.18 ms，漏节拍 13 → 25。web-544 的对应数值为 282.75 → 24.37 ms、1371.38 → 1944.83 ms、14 → 28。两张的录制活跃总量分别增加 72% 和 78%。固定 C1 也观察到相同方向。A 单独对 ③ 的影响较小且随样本而变，两张最重图的快照中位数下降。
- **第 1 步的录制结论在实际图稿上重现，快照结论只在部分样本重现。** 第 1 步在同色、等距、不重叠的纯矩形阵列上，80k 全量合并把录制从 228.61 降到 36.55 ms，首张快照从 140.77 降到 29.10 ms。本轮的 Rust 合并只覆盖满足条件的相邻路径，每批最多 32 个，图稿还带真实的颜色、尺度和场景结构。web-541 两项都获益，web-543 的首次快照却稳定变慢。稳态 raster 已使用库的位图缓存，口径和微基准的持续向量重放不同。 [第 1 步微基准](drawcall_micro.md)

## 建议

保留 **C** 作为独立优化候选，后续以 **C1A0** 为验证组合，默认关闭当前的 **A**。C 给 web-543、web-545、web-541 带来了可重复的首显收益。若首次快照也有回归约束，当前 C 需先解决 web-543 的约 34 ms 增量。A 适合单帧峰值优先的场景重新评估，当前 4 ms 方案在两张最重图上增加了漏节拍和约 0.4–0.6 秒的首显等待。

维持现有矩形候选范围，优先在真实图上扫每批上限、渲染后的轮廓间距和每批屏幕覆盖范围，同时测 ②b、③ 和完整显示。用 web-543 卡快照回归，用 web-541 和 web-545 卡录制与首显收益。现有结果支持矩形继续参与实验，凸多边形可单独设组验证。

## 像素和运行核对

- 每份图层为 872 × 1266（1,103,952 像素）。固定 A0 和 A1 分别切换 C，七样本五轮共 70 对，差异像素和最大通道差均为 0。固定 C 分别切换 A 的另外 70 对也逐像素一致。
- 视图为 1080 × 2340 物理像素，DPR 2.8125。每个有效试次有 19–47 帧稳态数据及一条匹配的原生快照。493 次有效采集的热状态为 0，AP 33.5–40.8 °C，机身 32.6–34.8 °C，电池 30.1–30.9 °C。
- 预检时 Android 的 120 Hz 浮点值触发了主机校验，改用 ±0.25 Hz 后开始正式采集。第五轮首次执行时，C1A0 的 web-545 等待首图超时，废弃未配齐的第五轮并用原 APK 重跑整轮。前四轮按 APK、SDK 和素材指纹核对后继续使用。
- 设备运行目录、推送中转文件和本次 VM Service 转发已清理。刷新率、常亮及原 APK 已恢复，原 APK 通过 SHA-256 复核。本轮直接复用两份 so，无需创建临时 worktree。

## 方法

- C0 使用 `c78eda18` 对应的 Android arm64 so，C1 使用工作区的合并版。APK 内两份 so 的哈希均与指定值一致。两个包解开后只有 `lib/arm64-v8a/libxvg.so` 的内容不同，Dart AOT SHA-256 均为 `a05b452aa55af268142deca0846ba86b7c451100aa7b44fb8c156eb63ebd12e5`。C1 同时含无尺寸 SVG 的默认视口处理，本次七张根 `<svg>` 都有 `width`、`height` 和 `viewBox`，未触发该分支。
- A0 用现有测试钩子将录制预算设为一天，并逐试次验证零续帧。A1 使用库默认的 4 ms 预算及复杂度条件。A0 和 A1 共用当前 Dart 录制器和 FRB worker 路径。这个对照隔离是否跨帧续录，A0 的录制器仍会执行切片检查，耗时可与上一轮使用 HEAD Dart 的基线不同。
- 真机为 Samsung SM-A566B（`R5CY2359S7D`），Android arm64 profile，Flutter 3.50.1、Dart 3.14.0、engine `4d35714800b9`，启动日志核验 Impeller Vulkan，设备目标刷新率 120 Hz。每轮以 `20261127 + 轮号` 打乱四组合与七样本，组间重启进程，同轮四组合共用样本顺序。附加样本 web-541、web-540 是排除已指定样本后路径减少最多的两张。 [上一轮语料排序](drawcall_merge.md)
- 分段和页面场景各从冷 Picture 缓存开始。②a 只计 FRB SSE 解码。②b 以录制钩子报告的活跃耗时求和，并取同次试验中最长切片，包含 `endRecording`，帧间等待计入完整显示。页面静止，转圈持续，SVG 字符串读好后交给真实 `StaticXvg`。通过图稿子树首次挂上实际绘制节点的帧号匹配 `FrameTiming`，完整显示从交付字符串到该帧 `rasterFinish`。
- ③取该图首个图片坐标缓存请求对应的原生 `DoMakeRasterSnapshot` 切片。每次请求与原生切片按提交顺序核对数量。稳态 raster 在首图完成、最后一次原生快照也完成后再等 50 ms，于首图登记后 450 ms 观测窗口内取实际帧耗时中位数。每个有效试次至少有五帧稳态样本。
- UI / raster 超时数统计首图阶段实际报告帧中，`buildDuration` / `rasterDuration` 各自超过单个刷新周期（约 8.33 ms）的数量。漏节拍由相邻 `vsyncStart` 时间差除以刷新周期后取整估计，无法从这些时间戳把每个漏掉的节拍归给某一线程。异步解码和首段录制可能发生在两帧之间，超时数和漏节拍需一起读。
- 性能窗口结束后，将同一个页面图稿区域单独包入 `RepaintBoundary`，读取初次绘制后再等 450 ms 的显示图层。比较预乘 RGBA 的每个像素及各通道绝对差。素材从 `E:\workspaces\svg-corpus\files` 经 adb 运行时推送。两个 APK 检查了 SVG 扩展名条目和解压后条目中的样本文件名及每份源文件的三个 192 字节片段，均未发现外部样本。

## 复现

在 `benchmark/bench_app` 用 Flutter 3.50.1 依次构建，分别令 `XVG_BENCH_JNI_DIR` 指向含 `arm64-v8a/libxvg.so` 的 C0、C1 目录，每次将输出复制为对应 APK。两份指定哈希的 so 已在本机找到，直接复用。

```powershell
flutter --no-version-check build apk --profile --no-pub --android-skip-build-dependency-validation --target-platform android-arm64 -t lib/ui_thread_decode_record_main.dart
python tool/run_drawcall_isolated.py --c0-apk $C0Apk --c0-so $C0So --c1-apk $C1Apk --c1-so $C1So --device R5CY2359S7D
python -m unittest discover -s tool -p 'test_drawcall*.py'
```

逐次计时、帧数据、原生切片、热采样、素材指纹、像素比较及设备恢复记录均在本机忽略文件中。 [原始 JSON](raster_cache_auto_isolated_raw.json)
