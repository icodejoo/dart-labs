# 超重静态 SVG 的分帧位图原型

> 结论：不转正。原型代码（库实现、单测、基准入口与脚本）未入库，补丁与文件备份在仓库外 `E:\workspaces\svg-corpus\bench-raw\progressive-raster-proto\`（基于提交 `b66a3567`）。

## 实现

- Rust 显示列表严格按绘制顺序回放。在顶层及纯裁剪栈内允许切批，每批重开继承的裁剪并在结束时退出。透明度和混合 `saveLayer` 从入层到匹配出层作为一个原子。单个路径或嵌入图像及其遮罩、模糊一起作为原子。超过预算的绘制原子单独成批，语料扫描记录最大原子及超预算原子数。
- 启用内部测试开关时，整图预测耗时大于 8 ms 且至少可切成两批才启用分帧。缓存准入仍检查路径及点数门槛。每个合成帧全局最多发起一次 `Picture.toImageSync`，在相同纹理原点先画累积结果、再画本批。较大视口沿用图片坐标分块，每块完成全部批次后才进入待发布网格。
- 首次生成时留白，分辨率重生成时沿用拉伸的旧位图。在屏网格齐备后一次切换。布局、目标分辨率或可见性变化、卸载及预算淘汰会释放失效的累积纹理。前一快照和下一目标同时计入全局 32 MiB 的 RGBA8 预算。
- 生产路径默认一次生成。内部 `@visibleForTesting` 开关为 true 时使用上述成本与分批规则。两种模式的静态 Picture 缓存键独立，冷加载时分别录制。

## 成本模型

每条命令累加下表各项的系数。点数含曲线控制点、独立描边几何和裁剪坐标。遮罩计入其重放路径和合成层。重开继承裁剪的耗时计入该批预算。

| 透明度或混合层 | 60.000 |

## 真机方法

- Galaxy A56，SM-A566B（`R5CY2359S7D`），Flutter 3.50.1，Android arm64 profile，Impeller Vulkan。用 `XVG_BENCH_JNI_DIR` 指向指定的 release so 目录。APK 中 `lib/arm64-v8a/libxvg.so` 的 SHA-256 为 `3cc70a8dd6f23a80aa5af0811dc25c63979c95e0dc7936918da473a53869403f`。
- 8 个样本各跑四种场景。用 Android 默认 `MaterialPageRoute` 跳转，弹窗在 260 ms 内从 0.82 倍放大到 1 倍，加载场景先显示静止页的 spinner 再挂载冷 SVG，`InteractiveViewer` 从 1 倍放大到 2 倍后停稳触发生成。跳转、弹窗和缩放预先录制向量 Picture，首次位图仍在实测阶段创建。加载场景两种模式均清空 Picture 缓存。
- 每个样本和场景都配对一次生成与分批生成，打散顺序并跨轮交换先后。每项统计先按轮计算，再取三轮中位数。动作窗口至少 760 ms，完成帧超出窗口时延长到完成帧。引擎报告的 vsync 间隔按 120 Hz 折算为少提交的帧数。
- 同时采集 Flutter `FrameTiming` 与原生 `DoMakeRasterSnapshot` 区间。表中“含快照 raster”将帧区间之外的快照时间归到其后首先完成的 raster 帧，避免漏掉帧外 GPU 工作或重复计时。完整显示耗时从 Dart 发起第一张位图请求算起，终点取最后一个所需原生快照完成后实际 raster 完成的场景帧。
- 在冷加载和缩放停稳后的计时窗口之外读回原始 RGBA8 纹理，按样本矩形逐字节比较。中间纹理峰值计入上一快照和下一目标，整体峰值还含就绪纹理。两项均是账本估算，不含引擎内部渲染目标、驱动临时分配和基准读回。

## 结论与参数

建议保留实验开关，暂不转正。web-543 冷加载最大单帧 raster 从 179.41 ms 降到 17.87 ms，完整显示从 189.29 ms 延长到 263.69 ms，端到端耗时也从 1182.23 ms 增至 1530.91 ms。放大场景里，web-078 的 28 个可见块从 28 次请求增至 112 次，完整显示从 243.99 ms 增至 958.04 ms。更低的峰值在同一场景中有时伴随更多掉帧，且实际分批的真机对比全部有像素差。

后续实验可沿用 8 ms 准入、5 ms 批目标、150 ms 分辨率停稳与 32 MiB 共享预算。量产前须验证跨帧保留原 GPU 渲染目标时的像素一致性，并把显示面积和可见块数纳入成本与完成时间评估。

APK 清单没有 SVG 素材。语料和 233KB 插画均由主机运行时推送。设备端输入输出目录、推送中转文件和 VM Service 转发均已清理，基准 APK 与常亮设置已恢复。

运行入口为 `bench_app/lib/raster_cache_progressive_main.dart`，主机驱动为 `bench_app/tool/run_raster_cache_progressive.py`，语料扫描为 `bench_app/tool/scan_raster_cache_progressive.dart`。主机清单使用 R2 原始 JSON 的 `corpus` 中 `id` 与本地 `file` 路径映射。APK 构建用 `--profile --target-platform android-arm64`，当前 Flutter 与既有 AGP 组合需在该次构建加 `--android-skip-build-dependency-validation`。
