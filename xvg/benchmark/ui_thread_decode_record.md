# 静态 SVG 在 UI 线程上的解码与 Picture 录制

10 张指定重图中有 6 张在两种测法中均为 12/12 次超过 8.33 ms。真实 `StaticXvg` 场景里，web-543、web-544 的②中位数分别为 **291.95 ms、333.09 ms**，首显提交分别逾期 **35、40 个帧周期**。耗时以 Picture 录制为主，这两张的 Dart 解码本身也超过预算。建议针对重图验证 Rust 分批交付和 Dart 按帧限量录制，中等图和 MDI 保留当前流程。

## 测法

- 设备为 SM-A566B（`R5CY2359S7D`），Android 17，Flutter 3.50.1，ARM64 profile，Impeller Vulkan。构建使用 `XVG_BENCH_JNI_DIR` 指向指定 release so 的目录。包内 `lib/arm64-v8a/libxvg.so` 与源文件的 SHA-256 均为 `3cc70a8dd6f23a80aa5af0811dc25c63979c95e0dc7936918da473a53869403f`。
- 三轮各从新进程启动。16 个样本逐轮打乱顺序，每个样本的分段和场景各测五次，试次间清空 Picture 缓存。每图每轮丢首测，合并剩余 12 次取中位数和最大值。四个中等对照为 web-103、web-056、web-075、web-029，按之前的场景路径计数挑选，覆盖约 100–450 条路径。两个 MDI 对照复用基准工程现有图标。
- **① Worker 往返上界**从 Dart 调用生成的 `callFfi` 前，到异步 `Uint8List` 交给 Dart codec 为止。这个窗口覆盖 Dart 请求编码、Rust 调度与解析、Rust SSE 序列化、消息投递和主 isolate 响应等待。原样 so 没有解析计时回传或内部符号，本次无法单独取得 Rust 解析纯耗时和 Rust SSE 编码耗时。分段对所有样本调用库的 worker 分支，便于与 MDI 对照统一比较。
- **②a Dart 解码**在主 isolate 直接包裹生成的 SSE codec `decodeObject`，沿用 FRB 的端口和回调链。载荷为收到的 `Uint8List.lengthInBytes`，含 SSE action 字节。路径是 `SvgScene.paths.length`，命令是顶层 `displayList.commands.length`。小图的真实同步场景用对应的 `decodeWireSyncType`。
- **②b Picture 录制**从库内 Canvas 录制钩子到 `onParseMiss` 回调，含命令回放、`endRecording`、同一录制函数的元数据汇总和清理。创建录制 Canvas 在打点之前，缓存插入在打点之后。②合计先在同一次试次内相加，再求统计量。
- **真实场景**用默认 `StaticXvg` 和持续动画的独立转圈区域。图稿使用 310 × 450 dp 的固定容器和 `BoxFit.contain`。构建使用当前 `xvg` 工作区，保留库默认的解析阈值和自动栅格缓存，既有的渐进栅格原型默认关闭。Dart 结果开始解码后继续记录帧，小图同步对照从 FFI 调用开始。录制完成后用 `PlatformDispatcher.frameData.frameNumber` 标记首显提交帧，再以帧号匹配 `FrameTiming`。正式三轮前做过一轮试跑，发现调度器时间戳与 `vsyncStart` 无法等值关联，改用帧号后从第一轮重跑。
- 帧窗口从结果事件前一帧到首显后四个已提交帧，止于卸载前。每次先取窗口内 Build、Raster 和调度等待峰值，再汇总这些峰值。用挂载前 140 ms 的转圈间隔中位数作周期。首显逾期帧是首显的 `buildFinish - vsyncStart` 折为整帧。全窗漏帧按相邻 `vsyncStart` 缺少的时隙估算。迟到的帧可能保留旧 `vsyncStart`，缺失时隙会记在它之后。两列衡量不同时间边界，可各自复算，Android 合成器实际呈现需要独立信号。
- 设备在轮次前及轮次内每约 2 秒记录系统热状态与 HAL 当前温度。采样期间临时将 Android 最低和最高刷新率设为 120 Hz，结束后恢复设置，实际 cadence 从转圈 `FrameTiming` 核对。

|---|---:|---:|---:|---:|---:|---:|
| 1 | 80 / 80 | 4,117 | 0 | 31.1–35.4 | 30.7–32.0 | 28.7–28.8 |

三轮 83 次热采样均为 0，未触发热重试。屏幕为 1080 × 2340，DPR 2.8125，场景上报约 120 Hz。转圈基线帧周期中位数为 8.318 ms，各试次周期中位数范围为 8.272–8.335 ms。

## 估算与建议

用 16 张图各自的分段中位数做单变量 OLS，分别以路径数和 SSE 字节数为自变量。②合计的拟合直接使用每图的同试次合计分布中位数。

| 时间 | 自变量 | 斜率（ms / 单位） | 截距（ms） | R² |
|---|---|---:|---:|---:|
| decode | 千路径 | 0.49 | -0.02 | 0.995 |
| decode | MiB | 6.42 | -1.82 | 0.747 |
| record | 千路径 | 2.86 | 4.04 | 0.997 |
| record | MiB | 37.94 | -6.70 | 0.753 |
| ui | 千路径 | 3.36 | 3.98 | 0.998 |
| ui | MiB | 44.54 | -8.61 | 0.753 |

路径模型受三张大量重复路径图支配。排除 web-543/544/545 后，②斜率变为 **4.74 ms/千路径**（R² 0.341）和 **4.00 ms/MiB**（R² 0.641）。全量拟合的斜率可作为量级参照，不能拿截距推单图阈值。准入和批次预算至少同时考虑路径数、几何点或动词数、SSE 字节数，以及昂贵绘制命令。

建议先在明确超预算的图上做分批原型。Rust 侧产出可独立解码的批次，Dart 每帧按时间预算消费一批或一部分，验收时分别记录解码、录制和首显帧。规则需覆盖 web-150 这种单条长路径，否则按路径数切分仍会留下超预算的录制块。中图和图标可继续一次交付。把输入侧派发和后续 Raster 各自留在独立预算里，便于验证每轮改动究竟消除了哪一段停顿。

## 复现与素材自查

在 `benchmark/bench_app` 执行。`$LegacySvg` 由操作者提供本机的 233KB 插画路径。

```powershell
$env:XVG_BENCH_JNI_DIR = (Resolve-Path ../../rust/target/aarch64-linux-android/release).Path
flutter build apk --profile --no-pub --android-skip-build-dependency-validation --target-platform android-arm64 -t lib/ui_thread_decode_record_main.dart
Copy-Item build/app/outputs/flutter-apk/app-profile.apk .dart_tool/xvg-ui-stage-profile.apk
python tool/run_ui_thread_decode_record.py --legacy-svg $LegacySvg
python tool/summarize_ui_thread_decode_record.py ../raster_cache_auto_ui_stage_raw.json
```

`benchmark/raster_cache_auto_ui_stage_raw.json` 已由现有 `.gitignore` 规则忽略。原始数据保留每次试次、各帧的时间戳、热状态和设备恢复结果。外部语料与 233KB 插画经固定中转名运行时推送。APK 无 SVG 文件及整份插画字节，新增源码不含任何输入 SVG 原文或插画本机文件名。aurora 使用基准工程已有素材，同样经运行时推送。

设备运行目录和中转文件已删除。原有基准 APK、常亮设置、最低和最高刷新率均已恢复。基准入口通过 `dart analyze`，汇总脚本的两个单测通过。
